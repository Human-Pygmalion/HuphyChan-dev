# 176. 학습에 쓴 무작위화 요소 전체: 근거와 정책 효과 (2026-10-18)

> 읽는 사람: 이 프로젝트에 새로 들어온 동료, 실기 담당 동료.
> 목적: 지금까지 학습에 넣은 무작위화 요소를 한 곳에 모은다. 요소마다 "무엇을, 왜, 넣었더니 어떻게 되었나" 를 적는다.
> 쓰기 규칙: ASD-STE100 을 한국어에 적용한다. 한 문장에 한 사실을 적는다. 정의한 용어는 바꾸지 않는다.
> 근거 원본: 코드 `mujoco-sim/mjlab/src/mjlab/tasks/velocity/config/pygmalion/env_cfgs.py`, 각 런의 `repro/launch_manifest.json`, 실험 노트(§9 출처 목록).
> 이 문서는 [[175_dr_requirements_from_measurements]] (실측에서 나온 요구) 를 대체하지 않는다. 175 는 "앞으로 넣을 것" 이고, 이 문서는 "지금까지 넣은 것과 그 결과" 이다.

## 0. 결론 먼저

1. **지금 실기에 올린 정책**(`rough_box_main_v11a`)은 다섯 가지 무작위화로 학습했다. 밀기, 발 마찰, 링크 질량·질량중심·관성, 엔코더 영점 치우침(±0.86°), 관측 잡음이다. 게인 무작위화와 명령 지연 무작위화는 없다.
2. **효과를 단독으로 잰 무작위화는 두 개뿐이다.** 게인 무작위화(C 런)와 명령 지연 무작위화(D 런)이다. 나머지는 모두 "켠 채로만 학습" 했다. 그래서 그 효과는 숫자로 말할 수 없다.
3. **낮은 게인에서 버티는 힘은 명령 지연 무작위화가 가장 크게 올렸다.** 게인 0.5 배 생존이 A 런 1/8, C 런 6/8, D 런 8/8 이다.
4. **두 무작위화 모두 대가가 있다.** 제자리 회전이 떨어진다 (A 53.5 % → C 48.0 %, D 37.7 %). D 런은 오르막 20° 넘어짐도 두 배가 되었다 (9.8 % → 18.0 %).
5. **시뮬레이터 생존은 실기 성공을 보장하지 않는다.** 실기 크기의 밀기에서 시뮬레이터는 0/48 넘어짐이었다. 실기는 2 초 안에 발산했다.
6. **배포 후보:** 실기 서기·밀기 시험은 D 런, 걷기·회전 시험은 C 런이다.

## 1. 용어 정의

| 용어 | 뜻 |
|---|---|
| 무작위화 (domain randomization) | 시뮬레이터의 물리 값이나 신호를 학습 중에 무작위로 바꾸는 것. 실물과 시뮬레이터의 차이를 정책이 견디게 한다. |
| 무작위화 크기 $f$ | 0 에서 1 까지 오르는 배율. $f=0$ 이면 무작위화 범위가 0 이고, $f=1$ 이면 전체 범위이다. 학습 반복 수에 따라 직선으로 오른다. 코드 이름은 `dr_factor` 이다. |
| 다시 뽑기 시점 | 무작위 값을 새로 뽑는 때. "재시작" 은 에피소드가 끝나고 새로 시작할 때이다. "매 정책 주기" 는 20 ms 마다이다. |
| 정책 주기 | 정책이 명령을 한 번 내는 간격. 50 Hz, 즉 20 ms 이다. |
| 단일 변인 비교 | 한 요소만 바꾸고 나머지는 같게 둔 두 런의 비교. 차이의 원인을 그 요소로 말할 수 있다. |
| 묶음 비교 | 여러 요소를 한 번에 바꾼 비교. 차이의 원인을 나눌 수 없다. |
| 따로 시험한 적 없음 | 켠 런만 있고 끈 런이 없다. 효과를 숫자로 말할 수 없다. |
| 게인 배율 | 실기에서 위치 게인 $K_p$ 와 속도 게인 $K_d$ 에 곱하는 수. 실기 시험은 몸통 0.3~0.5, 발목 1.0 으로 했다. |
| 실기 조건 시뮬레이터 | `tools/sim2real/real_condition_sim.py`. 실기의 게인 배율, 관측 지연, 응답 유실, 보호 한계를 시뮬레이터에 넣고 20 초 동안 서 있게 한다. 학습이 아니라 평가 도구이다. |

## 3. 요소별 근거와 효과

### 3-1. 무작위화 크기 곡선

- **무엇:** 학습 초반에는 무작위화를 끄고 걸음부터 배우게 한다. 그 뒤 범위를 직선으로 키운다.
- **근거:** 처음부터 전체 크기로 학습한 런이 무너졌다. 앞으로 속도 추종이 81 % 에서 26 % 로 떨어졌다 (`docs/61_velocity_tracking_review.md` §5). 그 뒤 "깨끗하게 먼저 배우고 무작위화를 올린다" 를 원칙으로 정했다 (`docs/62` 원칙 6).
- **효과 (같은 정책의 앞뒤 비교, 학습 1 회):** 깨끗한 저장본에 무작위화 곡선 1,000 회를 더 학습했다. 넘어지지 않는 밀기 한계가 0.7 → 1.5 m/s 로 올랐다. 넘어짐은 3/24 → 0/24 가 되었다. 걷는 속도는 0.60 → 0.64 m/s 로 거의 같았다 (`mlp_push_0919_1121`, 대장 194 행).
- **주의 (사고 두 번):** 곡선 구간을 학습 길이와 맞추지 않아 무작위화가 꺼진 채 학습한 적이 두 번 있다 (7 월 `gen21_rough_uneven2_p2`, 10 월 초 험지 시험 런들). 발사 전에 `env.yaml` 에서 곡선 구간을 확인해야 한다.
- **근거 없음:** 험지 런의 구간 2,000 → 8,000 회는 정량 근거가 없다. 구간 길이를 비교한 런도 없다.

### 3-2. 밀기

- **무엇:** 1~3 초마다 몸통 속도에 무작위 속도를 더한다. 수평 ±0.7 m/s 이다.
- **근거:** 사용자 지시 (2026-07-06 "외력도 넣어"). 범위의 하드웨어 근거는 없다. 다른 로봇 사례는 Unitree G1 ±1.5 m/s 이다.
- **효과 (묶음 비교):** 서기 전용 런 v7 → v7b 에서 밀기를 ±1.5 m/s 로 키우고 시작 자세 잡음을 함께 넣었다. 1.0 m/s 밀기의 분당 넘어짐이 12.1 → 0.0 회가 되었다. 대가로 서 있을 때 떨림이 19 배가 되었다 (관절 속도 합 0.04 → 0.77 rad/s) (`docs/reward_research/2026-09-17_standing_tremble.md` §2).
- **중요:** v7b 도 게인 0.5 배에서는 0/8 이었다. 강한 밀기는 낮은 게인 내성을 주지 않았다.
- **실기와의 관계:** 지금 배포 정책은 시뮬레이터에서 게인 0.8 이상이면 0.7 m/s 밀기에 0/60 넘어짐이다. 게인 0.6 에 실기 시간 조건을 더하면 50/60 넘어짐이다 (`docs/sim2real/2026-10-15_push_divergence_check.md`).

### 3-3. 발 마찰

- **무엇:** 발바닥 마찰 계수를 0.3~1.2 에서 고른다. 두 발은 같은 값을 쓴다.
- **근거:** 공개 보행 학습 코드의 기본값이다. 실측은 없다. 사람의 미끄러짐 시작 마찰은 약 0.2~0.4 이다 (`docs/16_dr_expansion.md`).
- **효과:** 따로 시험한 적 없음.
- **할 일:** 등반 지형(젖은 바위, 흙)에서는 아래 한계를 다시 정해야 한다 (175 §2).

### 3-4. 엔코더 영점 치우침

- **무엇:** 관절마다 ±0.86° 의 고정 치우침을 넣는다.
- **근거:** 공개 코드의 기본값이다. 실측 영점 오차는 처음에 최대 9.4° (왼무릎) 였다. 이것은 학습 범위의 11 배였다. 2026-10-14 재보정 뒤 남은 오차는 1~5° 이다. 실기 기록에서 오른 발목 크랭크 A 가 기본 자세보다 −5.6° 에 있었다 (175 §1-5).
- **효과:** 묶음 비교만 있다. 배포 정책에 발목 크랭크 고정 오차를 넣고 평가했다. 몸통 게인 0.4, 밀기 0.5 m/s 에서 −4° 는 6/8 넘어짐, +4° 는 1/8 넘어짐이었다 (`docs/sim2real/2026-10-17_real_stand_logs_gain031_051.md` §6).
- **주의:** 시뮬레이터는 이 치우침을 **목표값에만** 더한다. 정책이 보는 관절각에는 더하지 않는다. 실물의 영점 오차는 측정값과 기준을 함께 옮긴다. 이 차이의 영향은 재지 않았다.

### 3-5. 링크 질량·질량중심·관성

- **무엇:** 링크 7 종(몸통, 엉덩이 두 링크, 허벅지, 정강이, 발목 링크, 발)의 질량·질량중심·관성을 물리적으로 맞는 방식으로 바꾼다. 로봇 전체 질량은 약 22.5~26.2 kg (기준 23.6 kg) 이다.
- **근거:** 부품별 질량 불확실성을 추정해 범위를 정했다. 3D 출력 부품, 모터, 체결구 비율을 반영했다 (`docs/90_urdf_mjcf_pipeline_and_dr.md` §3). 최소 폭(질량 ±5 %, 질량중심 ±5 mm, 몸통 +10 %)은 판단으로 정했다.
- **효과:** 따로 시험한 적 없음.
- **알려진 구멍:** 모델의 발 질량은 0.618 kg 이다. 실측 발판은 0.182 kg 이다. 무작위화 범위로 이 차이를 덮지 못한다. 등반 때의 상체·배터리 질량은 아직 없다.

### 3-6. 관측 잡음

- **무엇:** 정책 입력에 균일 잡음을 더한다. 자이로 ±0.2 rad/s, 중력 방향 ±0.05, 관절각 ±0.01 rad 이다. 가치 함수에는 잡음이 없다.
- **근거:** 공개 코드의 기본값이다. 실측 잡음은 이보다 수십 배 작다 (자이로 표준편차 0.003 rad/s 이하, 중력 방향 0.0004~0.001). 그래도 여유로 둔다 (175 §2).
- **효과:** 따로 시험한 적 없음. 학습된 정책에서 잡음을 켜고 끄며 떨림을 재었다. 강한 밀기 런 v7b 는 잡음을 켜면 관절 속도 합이 0.77 rad/s, 끄면 0.00 이다 (`standing_tremble.md` §3).
- **안 넣은 것:** 일정한 치우침, IMU 값 멈춤, 관측 지연은 잡음에 없다.

### 3-7. 가치 함수 전용 무작위화 정보

- **무엇:** 가치 함수에 마찰, 질량 오프셋, 질량중심 오프셋, 최근 밀기, 무작위화 크기를 알려 준다. 정책(실기에 올라가는 쪽)은 이 값을 보지 않는다.
- **근거:** 가치 함수가 무작위화 값을 모르면 같은 상태에서 보상이 달라 학습이 흔들린다 (`docs/103` §2 V9).
- **효과:** 따로 시험한 적 없음.

### 3-8. 시작 자세

- **무엇:** 시작 위치와 방향은 항상 무작위이다. 관절각 잡음(±0.12 rad)과 몸통 기울기(±0.10 rad)는 선택이다.
- **근거:** 사용자 지시 (2026-09-16 "초기 자세가 틀려도 버티도록").
- **효과 (묶음 비교, v7b):** ±17° 관절 시작에서 2~3 초 안에 회복했다. 지금 배포 정책에는 관절각 잡음과 기울기가 없다.

### 3-9. 명령 분포

- **무엇:** 서기 명령 비율, 방향 유지 명령 비율, 앞으로만 명령 비율이다.
- **효과 (단일 변인 비교):** 서기 비율 0.1 과 0.3 을 비교했다. 제자리 회전이 51.1 % 대 9.5 % 였다 (씨앗 43) (`docs/experiments/2026-10-01_ab_v11_standing_seed43_compare.md`). 서기 동작은 같았다. 그래서 0.1 을 쓴다.
- **주의:** 같은 설정에서 학습 씨앗만 바꿔도 제자리 회전이 91 % 와 51 % 로 갈렸다. 학습 씨앗의 흩어짐이 크다.

### 3-10. 지형

- **무엇:** 상자 지형 5 종이다. 평지, 계단 오름(0~10 cm), 계단 내림, 상자 격자(0~12 cm), 기울어진 판(15° 까지)이 각 20 % 이다.
- **근거:** 높이맵 지형은 우리 발에서 접촉이 잘못 계산된다. 평평한 높이맵 위에서도 77~100 % 넘어졌다. 상자 지형은 0 % 였다 (`docs/experiments/2026-10-11_flat_vs_rough_policy_compare.md` §2).
- **효과:** 지형 자체를 무작위화 요소로 비교한 적은 없다.

### 3-11. 게인 무작위화 (C 런, 단일 변인 비교)

- **무엇:** 재시작마다 관절마다 $K_p$ 에 0.8~1.2, $K_d$ 에 0.7~1.3 배율을 따로 곱한다. 무작위화 크기 $f$ 를 따라 1 을 중심으로 범위가 커진다.
- **근거:** 다른 로봇 사례 (Cassie ±30 %, Walk These Ways 0.8~1.3, Isaac Lab 예제 0.8~1.2) (`docs/172` §4.2). 실기 감사에서 "게인 무작위화 없음" 을 높은 위험으로 지적했다. 모터 명령의 12 비트 양자화 오차는 1~2 % 뿐이다. 그래서 이 무작위화는 실제 응답의 불확실성(토크 상수, 온도, 필터)을 대신한다.
- **효과 (A 런 대비):**

| 지표 | A 런 | C 런 |
|---|--:|--:|
| 게인 0.5 배 생존 (8 번 중) | 1 | **6** |
| 게인 0.5 배 평균 생존 시간 | 5.4 초 | 16.6 초 |
| 게인 0.5 배 무릎 흔들림 | — | 6.9°, 0.86 Hz |
| 제자리 회전 중앙값 | 53.5 % | 48.0 % |
| 반대 방향 회전 | 3/64 | 7/64 |
| 학습 회전 추종 보상 (끝) | 0.857 | 0.772 (−9 %) |
| 직진 방향 치우침 | +4.48 °/s | +1.68 °/s |
| 오르막 20° 넘어짐 | 9.8 % | 6.6 % |

- **판정:** 걷기·회전 시험의 배포 후보이다 (`docs/experiments/2026-10-17_rough_gain_crank60_gaindr_v11a.md` §12).

### 3-12. 명령 지연 무작위화 (D 런, 단일 변인 비교)

- **무엇:** 매 정책 주기마다 섞는 비율 $d$ 를 0~1 에서 새로 뽑는다. 실제로 적용하는 명령은 $(1-d)\,a_t + d\,a_{t-1}$ 이다. 여기서 $a_{t-1}$ 은 직전에 실제로 적용한 명령이다. 따라서 최대 1 정책 주기(20 ms)의 지연과 같다.
- **근거:** Humanoid-Gym 의 같은 방식 (지연 0.5). 논문 범위 0~20 ms. 실기 감사의 "지연 무작위화 없음" 지적. 실측 명령 지연은 1~1.5 ms 로 작다. 그러나 실기 루프는 관절각을 1 정책 주기 늦게 받는다. 이 요소는 그 늦음을 대신하는 근사이다.
- **효과 (A 런 대비):**

| 지표 | A 런 | D 런 |
|---|--:|--:|
| 게인 0.5 배 생존 (8 번 중) | 1 | **8** |
| 게인 0.5 배 무릎 흔들림 | — | 0.6°, 0.34 Hz (공칭과 거의 같음) |
| 제자리 회전 중앙값 (지연 끔) | 53.5 % | 37.7 % |
| 제자리 회전 중앙값 (지연 켬) | — | 27.4 % |
| 반대 방향 회전 | 3/64 | 11/64 |
| 느린 회전 −0.25 rad/s 달성 | 34.5 % | 1.1 % |
| 학습 회전 추종 보상 (끝) | 0.857 | 0.692 (−19 %) |
| 직진 방향 치우침 | +4.48 °/s | **+0.47 °/s** |
| 오르막 20° 넘어짐 | 9.8 % | **18.0 %** |

- **판정:** 사전 가설은 "낮은 게인 내성은 게인 무작위화에서 온다" 였다. 이 가설은 틀렸다. 명령 지연 무작위화가 더 큰 효과를 냈다. 가능한 설명은 "게인이 낮으면 관절 응답이 늦어지고, 이것이 명령 지연과 비슷하다" 이다. 이 설명은 아직 검증하지 않았다.
- **배포:** 실기 서기·밀기 시험의 첫 후보이다 (`docs/experiments/2026-10-17_rough_gain_crank60_actdelay_v11a.md` §12).

### 3-13. 묶음 시험 런 (trial)

- **무엇:** 크랭크 55/2.5, 게인 무작위화, 명령 지연 무작위화, 부드러운 밀기, 엔코더 치우침 ±3° 를 한 번에 넣었다.
- **효과:** 게인 0.5 배 생존 8/8, 제자리 회전 23.4 % 였다. 원인을 나눌 수 없어 채택하지 않았다.
- **회전 손실 나누기 (학습 보상 기준, A 런 대비):** 묶음 −0.186, 명령 지연만 −0.165 (89 %), 게인 무작위화만 −0.085 (46 %). 합이 135 % 이므로 두 효과는 단순히 더해지지 않는다.
- **주의:** 묶음 런은 무작위화를 켠 채로 평가한 것으로 보인다. C·D 런은 끄고 평가했다. 그래서 23.4 % 는 C·D 런과 같은 조건의 숫자가 아니다.

### 3-14. 매끄러움 손실 (CAPS, 서기 전용 런)

- **무엇:** 입력에 잡음을 더해도 출력이 비슷하도록 손실을 더한다 (arXiv 2012.06644).
- **효과 (v7b 대비, 단일 변인 비교):** 떨림이 0.868 → 0.231 로 줄었다. 밀기 0~1.5 m/s 넘어짐은 0 을 유지했다. 대가로 마지막 정책의 두 발 간격이 26 cm → 48 cm 로 벌어졌다. 사용자가 "다리가 벌어진다" 로 기각했다 (`docs/experiments/2026-10-14_standonly_pose_audit.md`).
- **지금:** 쓰지 않는다.

- 게인 0.5 배 아래: 학습 범위를 넓히지 말고 실기를 0.8 배 이상으로 돌린다.

## 5. 주의 사항

1. **"명령 지연" 은 세 가지 다른 구현을 가리킨다.**
   - 본 저장소의 `PYG_ACTION_DELAY`: 직전 명령과 섞기, 최대 20 ms, 매 주기 새로 뽑기.
   - mjlab 의 구동기 지연: 물리 단계(5 ms) 단위의 정수 지연.
   - 배포 꾸러미(`vibecoded-audit-20261012`)의 `--act-delay`: 물리 단계 단위 정수 지연. 짧은 시험만 했다.
   - 문서나 코드에서 "명령 지연" 을 볼 때 어느 것인지 확인해야 한다.
2. **관측 지연은 학습에 쓴 적이 없다.** 실기의 실제 늦음은 관측 쪽(관절각 1 주기 늦음)에 있다. D 런은 그것을 명령 쪽 지연으로 근사했을 뿐이다.
3. **D 런의 정책 입력 "직전 행동" 은 섞인 값이다.** 실기는 정책의 원래 출력을 직전 행동으로 넣는다. 이 차이의 영향은 재지 않았다. D 런을 실기에 올리기 전에 배포 코드의 직전 행동 처리를 확인해야 한다.
4. **엔코더 치우침은 목표값에만 들어간다** (§3-4).
5. **학습 씨앗이 런마다 하나이다.** D 런의 씨앗별 제자리 회전은 1.9~83.4 % 로 흩어진다. 따라서 C 48.0 % 대 D 37.7 % 의 차이는 이 흩어짐 안에 있다. 반면 게인 0.5 배 생존 1/8 대 8/8 은 차이가 크다.
6. **실기 조건 시뮬레이터는 실기 발산을 재현하지 못했다.** 이 시뮬레이터에는 관측 잡음과 학습식 밀기가 없다. 시작 자세도 기본 자세이다.
7. **문서 사이의 불일치.** `docs/174`, `docs/175` 는 D 런 결과가 나오기 전에 썼다. 그 문서의 "게인 무작위화 덕" 은 이 문서 §3-12 로 고쳐 읽어야 한다. 대장의 "v7 은 무작위화 끔" 도 틀렸다. v7 은 무작위화 크기 0.49 까지 올라갔다.

## 6. 동료에게 권하는 것

1. **실기 서기·밀기 시험은 D 런 저장본으로 한다.** 게인 배율은 0.8 이상으로 한다. 0.5 는 시뮬레이터에서만 버틴다는 점을 기억한다.
2. **D 런을 올리기 전에 배포 코드를 확인한다.** 직전 행동 입력과 크랭크 게인 60/2.7 이 학습과 같아야 한다.
3. **다음 학습 후보 (결정 필요):**
   - 게인 무작위화와 명령 지연 무작위화를 둘 다 넣고, 회전 손실을 줄이는 런. 회전 손실 원인 조사가 먼저이다.
   - 같은 설정의 두 번째 학습 씨앗. C 와 D 의 차이가 씨앗 효과가 아닌지 확인한다.
   - E 런: 응답 유실, IMU 값 멈춤, 엔코더 ±3°. 구현이 먼저이다.
4. **새 무작위화를 넣을 때는 단일 변인 비교로 한다.** 묶음 비교는 원인을 나눌 수 없다. 이 프로젝트에서 묶음 런 결과를 해석하느라 시간이 들었다.
