## ELI5 — 세 문장

Menlo Research 가 자기 사람형 로봇(Asimov 1, 32 kg)을 걷게 한 학습 코드를 통째로 공개했습니다.
뼈대는 **우리와 같은 뿌리**(mjlab 의 속도 추종 과제를 Isaac Lab 으로 옮긴 것)라서 대부분이
익숙한데, **네 군데가 다르고 그중 두 군데는 우리가 며칠씩 헤맨 문제를 정면으로 푼 방식**입니다.
가장 큰 것은 "가만히 서 있기"를 **학습 표본을 더 주는 대신 보상 하나로** 해결한 점입니다 —
우리는 반대로 풀었다가 커리큘럼 정체와 보행 후퇴를 얻었습니다.

### ★ 3-1. 자세 항의 두 개조 — 그들이 mjlab 원본에 덧붙인 것

`mdp/rewards.py:306-400`. 원본 `variable_posture` 에 **두 가지를 더했습니다**(우리 쪽 mjlab
에는 둘 다 없음을 `grep` 으로 확인).

1. **교란을 받으면 허용폭을 넓힌다** (`:365-384`). 실제 속도가 명령에서 0.5 m/s 넘게 벗어나거나
   몸통이 0.15(중력 수평성분) 넘게 기울면 "교란 심각도"를 0→1 로 올리고, 허용폭을 최대
   **2.5 배**까지 넓힙니다(1.5 m/s 또는 0.6 에서 최대). 밀렸을 때는 발을 내딛고 몸을 기울여야
   살 수 있는데, 자세 항이 그걸 벌하면 **살아남기와 자세 지키기가 충돌**합니다. 그 충돌을
   교란 중에만 풀어 주는 장치입니다.
2. **느릴 때 자세 가중치 2 배** (`:392-398`). 명령 속력이 0.3 m/s 미만이면 자세 보상을 2 배로.

### ★ 3-2. "가만히 서 있기"를 보상으로 푼 방식 — 우리와 정반대

그들의 서기 허용폭도 **0.05 rad(2.9°)** 입니다(`velocity_env_cfg.py:404`) — **우리가 v5 에서
찾아낸 바로 그 죽은 항**과 같은 값입니다. 우리 v5 진단: 실제 자세가 허용폭의 2~5.6 배를 벗어나
있어서 exp(−8.7) = 1.7e−4, **기울기도 1.7e−4** 라 정책이 이 항을 통째로 무시했습니다.

그들은 이 문제를 **L1 항 하나로** 받쳤습니다 — `joint_deviation_l1`(`rewards.py:124-136`,
가중치 −1). L1 의 기울기는 **거리와 상관없이 항상 1**입니다. 기본자세에서 얼마나 멀든 "그쪽으로
돌아오라"는 신호가 같은 세기로 옵니다. exp 항이 멀리서는 죽고 가까이서만 살아 있는 약점을
정확히 메웁니다. 그리고 명령이 0.1 미만일 때만 켜지므로 걷기에는 간섭하지 않습니다.

**우리는 같은 문제를 과제 분포로 풀었습니다.** 서 있는 환경 비율을 0.1 → 0.3 으로 올려
표본을 더 준 것입니다. 결과(`[[2026-09-15_legonly_ab_v7_heading_revert]]` §1b-0, 2×2):

* 정지는 살아났습니다(v6b 자세추종 0.0023 → 0.8444).
* 그러나 **서 있는 환경이 학습 표본을 먹어** 커리큘럼 3→4 단계에서 모든 런이 5,400 회에
  강제 승급했습니다(0.1 은 3,200 회 자력 통과).
* v6b 는 보행도 후퇴했습니다(좌우차 −39.7 %, 비틀기 1.49).
* 중간값 0.175 인 v8 은 걷기는 최고지만 서 있을 때 12 초에 0.96 m 흘러갑니다.

**그들의 방식이면 서 있는 환경을 0.1~0.2 로 두고도 정지를 살릴 수 있다는 것이 가설입니다.**
검증은 우리 몫입니다(§9 1순위).

| 발 마찰 | 0.8~1.2 | 0.3~1.2 | 우리가 넓음 |
| 질량 | 없음 | 체결부 불확실성 JSON 기반 (2단계) | 우리만 |
| 리셋 관절 | **±0.5 rad, ±0.5 rad/s** 전 관절 | 0 (v7b 는 ±0.3) | 큼 |
| 리셋 몸통 | 피치 ±0.15, 롤 ±0.1 rad, **초기 각속도** ±0.5/±0.3 | 기울기·각속도 없음 | 있음 |

**그들이 공들인 곳은 "시간"입니다.** 무작위화 항목 셋(구동기 지연, 관측 지연, 이득)이 전부
**실물 제어 루프의 시간 오차**를 흉내냅니다. 모터 드라이버가 명령을 받아 토크를 내기까지,
관성측정장치가 값을 내고 그것이 정책까지 오기까지 걸리는 시간은 시뮬레이터에서 0 이지만 실물에서는
수 ms~수십 ms 입니다. 참조 동작 파일 이름이 `policy_delay_walk_slow` — "지연을 넣고 학습한
정책의 걸음" — 인 것도 같은 강조입니다.

**무게중심을 한쪽으로만 흔든 것**은 "모델보다 실물이 앞·위로 무겁다"는 것을 그들이 알고
있었다는 뜻으로 읽힙니다(대칭이 아니라 **알려진 오차 방향을 중심으로** 흔드는 방식). 우리는
전신 질량이 +1.4 % 로 맞는다는 것만 알고 무게중심의 방향 오차는 재지 않았으므로 따라 할 근거가
없습니다.

## 6. 동작 사전분포 — 어떻게, 왜

### 6-1. 무엇을 하는가

판별기(은닉층 256·256, ReLU)가 **(현재 상태, 다음 상태)** 쌍을 보고 "참조 동작에서 온 것이면
+1, 정책에서 온 것이면 −1" 을 맞히도록 **최소제곱 손실**로 학습합니다(`amp_ppo.py:273-292`).
여기서 상태는 **관절각 23 개 + 관절속도 23 개**뿐입니다 — 몸통 위치·속도는 보지 않습니다
(`amp_env_cfg.py:23`). 정책은 판별기 점수 D 로부터

  스타일 보상 = max(0, 1 − ¼(D − 1)²)

를 받습니다(`discriminator.py:95`, Peng 외 2021 과 같은 식). 과적합을 막는 장치 셋:

* 참조 쪽에만 **기울기 벌점** λ = 10 (`:99-112`)
* 가중치 감쇠 — 몸통 1e−3, **머리 1e−1** (머리를 세게 눌러 판별기가 과신하지 않게)
* 정책 표본 **재생 버퍼** 10 만 개(`replay_buffer.py`) — 최근 것만이 아니라 지난 정책 표본까지 섞어 판별

### 6-2. 보상을 어떻게 섞나 — 스타일은 작다

`amp_ppo.py:139-144`:

  전체 보상 = 0.7 × 과제 보상 + 0.3 × (0.3 × 스타일 보상 × 게이트)

스타일 보상의 실효 가중은 **0.09** 입니다. 과제 보상을 이끄는 것이 아니라 **자세의 버릇을
살짝 잡아 주는 정도**입니다. 그리고 **게이트**: 명령 크기가 0.1 미만(서 있기)이면 스타일 보상을
0 으로 만듭니다(`:353-366`). 참조가 걷는 동작뿐이라 서 있는 것을 "안 닮았다"고 벌하지 않도록.

### ★ 6-3. 참조 동작의 정체 — 사람 동작이 아니라 **자기 정책의 녹화**

`motions/policy_delay_walk_slow.npz` 를 열어 쟀습니다.

| | 값 |
|---|---|
| 길이 | 2,472 프레임 × 50 Hz = **49.4 초**, 한 덩어리 |
| 평균 속력 | 골반 **0.36 m/s** (느린 걸음), 방향이 계속 바뀜 |
| 요 각속도 | −0.53 ~ +0.37 rad/s (**회전 포함**) |
| 골반 높이 | 0.625 m ± 5.7 mm |
| 무릎 | 0.3° ~ 72.6° (스윙 때 크게 굽힘) |
| 형식 | 관절 23 + 몸체 26 개의 위치·자세·속도 — whole_body_tracking/beyondAMP 계열 내보내기 형식 |

이름 그대로 **지연을 넣고 학습한 이전 정책을 굴려서 녹화한 걸음**입니다. 동작 포착 장비도,
사람 동작을 로봇 관절로 옮기는 재매핑도 없습니다. "마음에 드는 걸음이 한 번 나왔으면 그것을
참조로 박아 다음 학습이 그 버릇을 유지하게 한다" — **자기 증류**에 가까운 쓰임입니다.

### 6-4. 주의 — 판별기 특징 정규화기의 이상한 갱신

`discriminator.py:114-121` 은 달리는 평균·분산을 갱신할 때 **이미 정규화된 값**을 넣습니다.
그러면 통계가 원래 특징의 평균·분산으로 수렴하지 않고, 자기 자신을 되먹이는 고정점으로
갑니다. 실수가 아니라 **의도적으로 재현한 것**으로 보입니다 — 시험 코드가 바로 이 동작을 정답으로
단정합니다(`tests/test_amp_components.py:14-50`, 이름이 "기준 구현의 수식과 일치"). 기준 구현을
그대로 옮긴 것입니다. **우리가 이 방식을 가져온다면 이 부분은 따라 하지 말고 원래 값으로
갱신할 것.** 실제 성능에 얼마나 영향을 주는지는 확인하지 않았습니다.

## 7. 특이한 트릭 — 한 줄씩

1. **시간 오차 세 겹 무작위화** — 구동기 0~25 ms, 관성측정 0~20/0~40 ms, PD 이득 ±20 %.
2. **서기 전용 L1 편차 항** — exp 자세 항이 멀리서 죽는 것을 기울기 일정한 항으로 받침.
3. **교란 적응 자세 허용폭** — 밀리거나 기울면 자세 허용폭을 최대 2.5 배로.
4. **자기 정책 녹화를 참조로 쓰는 동작 사전분포** — 동작 포착·재매핑 없이 걸음 버릇을 고정.
5. **스타일 보상의 서기 게이트** — 참조에 없는 동작(서기)은 스타일로 벌하지 않음.
6. **발 걸림 항** — 수평 접촉력이 수직의 4 배를 넘으면 벌점. 턱에 발끝이 걸리는 것을 직접 잡음.
7. **상한 없는 접촉력 벌점** — 몸무게 1.1 배(350 N)부터 선형, 포화 없음.
8. **한쪽으로만 흔드는 무게중심** — 알려진 모델 오차 방향을 중심으로.
9. **커리큘럼 없음, 무작위화 처음부터** — 좁은 명령 상자와 짝.
10. **관측 순서를 모터 버스 순서에 맞춤** — 배포 순서 오류를 구조로 차단.
11. **동작 사전분포 관측 항 목록을 시작 시 단정** (`amp_env_cfg.py:47-55`) — 판별기의 정책 쪽 특징과
    참조 쪽 특징이 어긋나는 것을 실행 시점에 막음.

### ★ 곁다리 확인 — 체공 게이트가 v7 의 "느린 회전 무시"를 설명하는가

v7 은 회전 명령 ±0.25 를 거의 무시했습니다(18 %·−0.4 %). 체공 보상은 명령 합이 **0.5 를
넘을 때만** 켜지므로(우리도 그들도), 제자리에서 ±0.25 로 돌라고 하면 **발을 들 이유가 없습니다**.
그럴듯한 설명이지만 **데이터가 부분적으로 반박합니다** — ±0.5 도 "0.5 초과"가 아니라 게이트가
꺼지는데, v7 은 ±0.5 에서 **91~94 %** 로 가장 잘 돌았습니다. 게이트가 원인이라면 ±0.5 도 나빠야
합니다. **단독 원인은 아닙니다.** 다음 사람이 같은 길을 다시 가지 않도록 적어 둡니다.

## 9. 우리 학습에 넣으면 개선될 것 — 우선순위

각 항목에 **우리가 측정한 문제**, **그들의 방식**, **예상 효과**, **위험**, **검증 방법**을 붙였습니다.
어느 것도 아직 학습해 보지 않았습니다 — 전부 가설입니다.

### 1순위 — 정지를 보상으로 고치고, 서 있는 환경 비율을 되돌린다

| | |
|---|---|
| 우리 문제 | 서기 자세 항이 죽어 있음(v5, 기울기 1.7e−4) → 서 있는 비율을 올려 해결 → **커리큘럼 정체(5,400 강제 승급) + 보행 후퇴(v6b) + 흘러감(v8 0.96 m)** |
| 그들의 방식 | 서기 전용 L1 관절편차 항(−1, 명령 < 0.1 에서만) + 저속 자세 가중 ×2, 서 있는 비율 0.2 |
| 제안 | v7 설정(방향유지 0.3)에 **L1 항만 추가**하고 서 있는 비율을 **0.1** 로 되돌린 팔 하나 |
| 예상 | 서기 품질은 유지(v7 수준: 발 뗀 시간 1.3 %, 흘러감 0.35 m), **게이트 자력 통과 회복(3,200 회)**, 걷기는 v8 쪽으로 |
| 위험 | L1 은 기본자세에서 **꺾여 있어** 영점 근처에서 떨 수 있음 — 우리는 떨림 문제(v7b)를 이미 안고 있음. 떨림 지표를 같이 잴 것 |
| 검증 | 같은 세 판정(정지·보행·회전)을 같은 도구·같은 씨앗으로 + 게이트 승급 시점 + 떨림 |
| 비용 | 보상 한 항, 설정 한 줄 |

**이것을 1순위로 두는 이유**: 지난 열흘의 거의 모든 실험(v6b·v7·v8, 2×2, 게이트 제외 장치)이
"서 있는 환경 비율"이라는 한 손잡이를 돌리며 생긴 부작용을 쫓은 것이었습니다. 그 손잡이를
돌리지 않아도 되는 길이 있다면, 두 목표(정지·보행)를 한 정책에 담는 가장 짧은 길입니다.

| 제안 | `variable_posture` 에 같은 개조 — 떨림 A/B(CAPS·립시츠·스펙트럼 정규화)와 **별개 축**이므로 따로 |
| 위험 | 교란이 아닌데 교란으로 오인되는 구간(빠른 걸음의 순간 오차)에서 자세가 풀릴 수 있음 |

### 4순위 — 지면 반력 벌점의 문턱을 낮추고 포화를 없앤다

| | |
|---|---|
| 우리 문제 | #13: v6b 한 발 p99 **5.43 몸무게**, 3.5 몸무게 초과 시간 8.86 %, 최고 14.7 몸무게 |
| 그들 | **1.1 몸무게**부터, **상한 없이** 선형 |
| 우리 | **2.6 몸무게**부터, **6.0 몸무게에서 포화** — 그 위의 충격은 벌점이 더 커지지 않음 |
| 제안 | 문턱을 1.5~2 몸무게로, 포화를 없애거나 크게 올린 팔. **발 걸림 항**도 함께 |
| 위험 | 상한 없는 벌점은 드문 거대 충격 하나가 기울기를 지배할 수 있음 — 단계별 벌점 크기에 상한을 두는 것은 남겨 둘 것. 이 프로젝트는 **보상 항 하나를 크게 올렸다가 해킹당한 이력**이 있음(착지 출력 보상 → 11.5 몸무게) — 그건 양의 보상이었지만 조심할 것 |

### 5순위 — 동작 급변 벌점: 그들은 우리의 5 배

그들 −0.5, 우리 −0.1. 떨림 대책으로 직결되는 숫자라 적어 둡니다. 다만 **이미 진행 중인 떨림
A/B 는 "시간축을 누르면 둔해진다"는 근거로 일부러 상태축 방법을 택했습니다**(`[[2026-09-18_legonly_ab_v9_caps]]`).
그들은 −0.5 로도 밀기 회복을 학습합니다 — **그 A/B 에 비교 팔 하나로 넣을 가치**가 있다는 정도로
둡니다. 단독 권고는 아닙니다.

### 6순위 — 리셋 다양화

그들은 모든 관절을 ±0.5 rad(29°)·±0.5 rad/s 로, 몸통을 피치 ±0.15·롤 ±0.1 rad 기울이고
초기 각속도까지 줍니다. 우리는 v7b 에서 ±0.3 rad(`PYG_RESET_JOINT_NOISE`)까지 갔습니다.
**넘어진 뒤 일어서기·들어 올렸을 때의 발작**(#9·#17)과 관련된 방향이라, 그 과제를 할 때 같이 볼 것.

### 7순위(장기) — 동작 사전분포: 참조를 **v8 의 걸음**으로

| | |
|---|---|
| 우리 이력 | 관절각 참조 **추종**(위상을 맞추는 방식)은 여러 번 실패함 — 위상 불일치 |
| 차이 | 동작 사전분포는 위상을 맞추지 않음. "닮았는가"만 봄 |
| ★ 착상 | 그들처럼 **자기 정책의 녹화**를 참조로 쓴다면, 우리에게 딱 맞는 후보가 있음 — **v8 의 걸음**(비틀기 0.34·표류 10.1°·좌우차 +9.5 %, 역대 최고). v8 은 잘 걷지만 못 돌고, v7 은 돌지만 덜 잘 걷는다. **방향유지 0.3(v7 의 회전) + v8 걸음을 참조로 한 사전분포**면 둘을 한 정책에 담을 수 있는가가 질문 |
| 비용 | 판별기·재생 버퍼·주자(runner) 연결 — mjlab 쪽에 새로 붙여야 함. 이 노트의 다른 항목보다 한 자릿수 큰 일 |
| 주의 | 참조가 직진 위주면 **회전을 "안 닮았다"고 벌할 수 있음** — 그들처럼 게이트를 두거나 회전이 섞인 녹화를 쓸 것. §6-4 의 정규화기 동작은 따라 하지 말 것 |
