[A1] 숫자가 아닌 목표(NaN)를 넣으면 전송을 막는가
  판정     지킴
  넣은 것  무릎 목표 = NaN (0으로 나누기·발목 계산 발산에서 실제로 생김)
  기대     거부 이유 'nan' 이 세어지고, 무릎으로 아무 프레임도 안 나감
  나온 것  거부 {'nan': 1} · 만들어진 명령에 무릎 없음 · 선에 나간 무릎 명령 없음
           막지 못하면 NaN 이 인코딩에서 최대값이 되어 720도 명령이 됩니다.

[A2] 무한대(inf) 목표도 같이 막히는가
  판정     지킴
  넣은 것  무릎 목표 = +무한대
  기대     'nan' 과 같은 통로로 거부
  나온 것  거부 {'nan': 1}

[A3] 측정값이 NaN 이면(센서 이상) 명령을 막는가
  판정     지킴
  넣은 것  목표는 멀쩡한 10도, 그런데 현재 각도가 NaN
  기대     전송 안 함 (현재를 모르면 폭주 상한을 못 잼)
  나온 것  보낼 수 있나=False, 이유=RejectReason.NOT_FINITE

[A4] 한 번도 응답하지 않은 모터에 명령이 나가는가
  판정     지킴
  넣은 것  무릎이 한 번도 상태를 보내지 않은 상태에서 10도 명령
  기대     거부 이유 'nostate'. 현재 위치를 모르면 보내지 않음
  나온 것  거부 {'nostate': 1} · 만들어진 명령에 무릎 없음

[A5] 가동범위 밖 목표를 하드스톱 안쪽으로 자르는가
  판정     지킴
  넣은 것  무릎이 60도에 있는 상태에서 목표 200도 (하드스톱은 -20.65~74.79도). 폭주 상한(50도)보다 한계가 먼저 걸리도록 자리를 잡음
  기대     하드스톱에서 3도 안쪽인 71.79도로 잘리고 'limit' 이 세어짐
  나온 것  실제 목표 71.79도, 잘린 내역 {'limit': 2}

[A6] 한계를 아직 안 쟀을 때 그 검사가 무슨 일을 하는가
  판정     구멍
  넣은 것  A5 와 똑같은 상황인데, 실측값만 지금 저장소 상태(전부 '안 잼')로 둠. 설정 파일의 한계 검사는 '켜짐'
  기대     A5 처럼 71.79도로 잘려야 할 것 같지만…
  나온 것  한계 클리핑 0회 · 폭주 상한만 걸려 목표 109.99도 (한계보다 38도 밖)
           한계값이 비어 있으면 검사가 **그냥 통과**합니다(limits.clamp 첫 줄). 설정에 '켜짐' 이라고 적혀 있어도
           실제로 지켜 주는 것은 없습니다. 실물에서는 커미셔닝(sweep)으로 한계를 채우기 전까지 이 상태입니다. 다만 힘을
           넣는 문(enable)이 따로 막으므로 E1 과 함께 보아야 합니다.

[A7] 속도 제한이 한 주기 전진량을 묶는가
  판정     지킴
  넣은 것  0도에 있다가 갑자기 300도 명령 (벤치 설정: 초당 902도까지)
  기대     직전 명령에서 9.02도만 나아감
  나온 것  실제 목표 9.02도, 잘린 내역 {'rate': 1}

[A8] 폭주 상한이 측정 위치에서 너무 멀리 못 가게 하는가
  판정     지킴
  넣은 것  무릎이 0도에 있는데 200도 명령 (실물 설정: 폭주 상한 50도)
  기대     한계로 먼저 잘리고, 그래도 멀면 현재+50도까지만
  나온 것  실제 목표 49.99도, 잘린 내역 {'limit': 2, 'jump': 1}

[A9] 세 관문의 순서가 설계대로인가 (한계 → 속도 → 폭주)
  판정     지킴
  넣은 것  목표 500도, 한계 -20~80도, 한 주기 9.02도, 폭주 상한 50도
  기대     77도로 잘린 뒤 9.02도까지만 나아감 → 최종 9.02도, 기록은 limit+rate
  나온 것  최종 9.02도, 기록 ['limit', 'rate']

[A10] 전송이 끊겼다 되살아날 때 그동안 벌어진 만큼 한꺼번에 나가는가
  판정     지킴

  기대     공백을 속도 예산으로 치지 않고 한 주기분(9.02도)만
  나온 것  실제 목표 9.01도
           2026-09-07 벤치에서 40도·44도가 한 번에 나간 사고가 이 자리였습니다.

[A11] 아주 첫 명령에도 속도 제한이 걸리는가
  판정     지킴

[A12] 실물 설정(robot_v1.0.yaml)에 속도 제한이 있는가
  판정     구멍
  넣은 것  실물 설정 파일에 적힌 안전값 그대로
  기대     벤치처럼 속도 제한이 적혀 있어야 안전
  나온 것  무릎 속도 제한 = None (없음)
           벤치 설정에는 max_vel_deg_s 가 있는데 실물 설정에는 아직 없습니다. 실물로 옮길 때 이 줄이 빠지면, 남는
           것은 폭주 상한 50도 하나입니다 — 그것은 속도가 아니라 힘을 자르는 장치라 성격이 다릅니다.

  바이트로 바꿀 때
==============================================================================

[B1] 마지막 관문이 NaN 을 막아 주는가
  판정     주의
  넣은 것  목표 각도 NaN 을 바이트로 바꿔 봄
  기대     사람들은 '범위로 잘리니까 괜찮다' 고 생각하기 쉬움
  나온 것  바이트 값 65535 = 720.2도
           크거나 작다는 비교가 NaN 에 대해 전부 거짓이라 그냥 통과합니다. 그래서 A1 의 검사가 **유일한** 방어선입니다.
           순서를 바꾸면 안 됩니다.

[B2] 힘(kp)을 낮추다가 0이 되어 버리는 자리가 있는가
  판정     구멍
  넣은 것  RS04 에 여러 kp 값을 넣어 실제로 나가는 값을 봄 (설정 파일 기본 kp=10, 문서가 권하는 시작법은 '0.1배로 낮춰 시작')
  기대     낮추면 낮은 대로 나가야 함
  나온 것  10→8(9.768) · 5→4(4.884) · 2→1(1.221) · 1.5→1(1.221) · 1.221→0(0.000) · 1→0(0.000) · 0.5→0(0.000)
           RS03·RS04 는 kp 를 0~5000 범위의 12비트로 싣습니다. 한 칸이 1.221 이고 내림이라 **1.2210
           미만은 전부 0**, 즉 힘이 아예 안 나갑니다. robot_v1.0.yaml 이 권하는 `--gain-scale
           0.1` 은 kp 10 → 1.0 → 0 입니다. 오류도 경고도 없이 '명령은 나가는데 안 움직임' 이 됩니다.

[B3] 감쇠(kd)에도 같은 자리가 있는가
  판정     주의
  넣은 것  RS04 에 여러 kd 값
  기대     한 칸이 0.0244 이므로 그 미만은 0
  나온 것  1→40 · 0.502→20 · 0.1→4 · 0.0244→0 · 0.02→0
           정책이 쓰는 kd 0.502 는 안전합니다(20칸). 0.1배로 낮추면 0.0502 → 2칸이라 아직 살아 있지만,
           여기서 더 낮추면 감쇠가 사라집니다.

[B4] 범위를 넘는 목표가 반대편으로 감기지는 않는가
  판정     지킴
  넣은 것  목표 2000도 (인코딩 한계는 ±720도)
  기대     +720도쪽으로 잘림. 음수로 감기면 반대로 튐
  나온 것  720.2도

           온도는 정확히 읽히고 화면·기록에도 나오지만, **그 값으로 무엇을 하는 코드가 어디에도 없습니다.** 모터 자체의
           보호(RS04 기준 145도)만 남습니다. 우리 벤치 규칙인 50도 차단은 아직 로봇 프로그램에 없습니다.

[F2] 모터가 '고장' 이라고 답하면 루프가 알아채는가
  판정     구멍
  넣은 것  무릎이 매 응답마다 고장·경고 표시를 켠 채로 답함
  기대     그 표시를 보고 멈추거나, 최소한 기록에 남아야 함
  나온 것  관찰 항목에 고장/경고 칸 없음 · 루프 20주기 정상 종료
           고장·경고·동작모드 세 가지는 **매 응답에 공짜로 실려 옵니다.** 그것을 푸는 함수(decode_flags)까지
           만들어져 있고 시험도 있는데, 실제 수거 경로(bus.collect)가 그 함수를 부르지 않습니다. 고장을 알려면 따로
           물어봐야 하고(read_fault), 그것은 사람이 커미셔닝 화면에서만 합니다.

[F3] 정말로 힘이 켜졌는지 모터에 확인하는가
  판정     주의
  넣은 것  켜기 명령을 보냈지만 무릎은 여전히 '힘 꺼짐' 상태로 답함
  기대     모터가 보고하는 동작모드로 대조해야 함
  나온 것  프로그램이 아는 값 = True (보낸 명령 기준이지 물어본 값이 아님)
           `is_torque_on` 은 '내가 켜기 명령을 보냈다' 만 뜻합니다. 모터가 실제로 켜졌는지는 응답의 동작모드에 들어
           있는데 F2 와 같은 이유로 안 봅니다. 벤치에서 '명령은 나가는데 안 움직임' 을 진단할 때 바로 이 값이
           필요했습니다.
