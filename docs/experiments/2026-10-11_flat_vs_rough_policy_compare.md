## 2. 같은 험지 비교 (`analysis/terrain_eval.py`, 256 환경, 같은 씨앗, 밀기 없음, 앞으로 0.6 m/s 고정)

|---|---|---|---|

- 6 초(3.6 m) 기준 — 20 초로 재면 로봇이 8 m 타일을 벗어나 다른 지형으로 들어가 단계별 값이 섞였다(20 초 값도 순위는 같음, `terrain_eval_rough_ab.json`).
- **원인 확인 (2026-10-11)**: 높이 지도형 타일(비탈·물결·무작위 거친 땅)은 가장 쉬운 단계 0 에서도 세 정책 모두 77~100 % 넘어진다(평탄·계단 타일은 0 %).
  컴파일된 모형에서 타일마다 높이 지도를 직접 읽어 보니 **단계 0 의 비탈·물결 높이 지도는 완전히 평평**(높이 차 0.00 m, 단계마다 0.23 m 씩 증가 — 생성은 정상)하다.
  그런데도 평평한 높이 지도 위에서는 걷다가 주저앉고(발동 직전 몸통이 발 위 0.57 m, 평소 0.85), 같은 평평함의 상자형 바닥에서는 0 %. 제자리에 서 있을 때는 두 바닥 모두 정상.
  즉 **학습 시뮬레이터(MuJoCo-Warp)의 높이 지도 접촉이 걷는 발에서 잘못 작동**한다. CPU MuJoCo 의 높이 지도(산길 시험)에서는 같은 정책들이 잘 걷는다 — Warp 쪽만의 문제.
  학습 로그의 "height field collision overflow ≥ 50" 경고(Warp 의 높이 지도 접촉 개수 상한 `mjMAXCONPAIR` = 50)는 드물어서(2.9 억 걸음에 36~62 번) 직접 원인은 아닌 것으로 본다.
  발목 연결봉 폭주(물결 타일에서 측정)도 같은 뿌리일 가능성이 크다 → [[162_next_plan_rough_policy]] 단계 2·5. 정책 간 비교는 같은 조건이라 유효.
