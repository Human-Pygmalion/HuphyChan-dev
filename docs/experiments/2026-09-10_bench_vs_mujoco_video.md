## 한 줄 결론

**같은 명령을 받은 실물 모터와 MuJoCo 를 한 화면에서 동시에 볼 수 있게 됐습니다.**
왼쪽은 카메라로 찍은 실물, 오른쪽은 **MuJoCo 가 자기 렌더러로 그린 3차원 그림**,

영상 22초, 산출물 `docs/assets/motor_bench_vs_mujoco_rs04.mp4`.

## ★ 앞선 보고 정정 — MuJoCo 3차원 렌더는 됩니다

이전 판에서 오른쪽 그림을 제가 **손으로 그린 시계 눈금**으로 내면서, 이유를 이렇게
적었습니다:

> "물리는 MuJoCo 가 풀지만 그림은 제가 직접 그렸습니다 — 이 컴퓨터에 오프스크린 OpenGL 이
> 없어(EGL·OSMesa 둘 다 실패) MuJoCo 자체 렌더러를 못 씁니다"

**이 진단이 틀렸습니다.** 다시 확인한 결과:

| 확인한 것 | 결과 |
|---|---|
| 그래픽 카드·드라이버 | NVIDIA GeForce RTX 5060 Ti · 570.195.03 |
| EGL 로 화면 없이 OpenGL 열기 | `chooseConfig 1` · `bindAPI 1` · `makeCurrent 1` · **OpenGL 4.6** |
| `MUJOCO_GL=egl` 로 `mujoco.Renderer` | **`render()` 가 `(240, 320, 3)` 그림을 정상 반환** |

제가 실패로 본 오류(`EGLError`)는 **렌더가 끝난 뒤 소멸자(`Renderer.__del__`)가 정리하면서
내는 뒷정리 잡음**이었습니다. 출력의 꼬리만 보고 "렌더가 실패했다"고 판단한 것이 원인입니다.
**앞으로 오류 문구는 어느 단계에서 났는지까지 보고 판단합니다.**

## 어떻게 두 그림의 각도를 맞췄나

카메라 각도 맞추기(`track_pointer.py` + `fit_sync`)에서 나온 관계는

```
실제 각도 = 1.3078 x (영상에서 잰 각도) + 117.72     설명력 0.974
```

여기서 실제 각도가 0 일 때 영상 각도는 **-90도**, 즉 나무 막대가 **화면에서 위**를
가리킵니다. 그리고 실제 각도가 커지면 영상에서 **시계 방향**으로 돕니다.

그래서 MuJoCo 카메라를 이렇게 세웠습니다.

| 무엇 | 값 | 왜 |
|---|---|---|
| 방위각 | 90도 | 가로축 +x 가 화면 오른쪽, +y 가 화면 위가 되도록 |
| 내려보는 각 | 46도 | 실제 카메라가 모터를 내려다보는 각과 비슷하게 |
| 관절 각도 | `90도 − 실제각도` | 0 에서 위를 보고, 커지면 **시계 방향** = 실영상과 같은 방향 |

확인은 눈으로 했습니다. 실제 각도 0.0도인 순간(3.0초)에 실영상의 나무 막대와 MuJoCo 의
초록 막대가 **둘 다 위**를 가리키고, +13도인 순간(12.4초)에는 **둘 다 같은 쪽으로 같은
만큼** 기울어 있습니다.

## 화면 구성 — 빈 곳이 없게

1600 x 900 화소를 세 덩어리로 **딱 붙여서** 씁니다. matplotlib 의 축 여백이 아니라
그림을 화소 단위로 이어 붙이기 때문에 남는 흰 자리가 없습니다.

| 위치 | 크기 | 내용 |
|---|---|---|
| 제목띠 | 1600 x 46 | 모터 이름과 넣은 세 값(관성 0.0773 · 마찰 0.519 · 점성 0.0275) |
| 왼쪽 위 | 800 x 520 | 실영상. **패널과 같은 가로세로비로 잘라** 늘어나 보이지 않게 |
| 오른쪽 위 | 800 x 520 | **MuJoCo 3차원 렌더.** 초록=MuJoCo, 검정=실물 기록, 회색=명령 |
| 아래 | 1600 x 334 | 네 곡선 + 지금 시각을 가리키는 빨간 세로선 |

세 막대는 **높이를 달리 놓아** 서로 가리지 않고, **전부 질량 0** 이라 물리 계산에
들어가지 않습니다.

그래프는 **한 번만 그려 화소로 들고 있다가** 프레임마다 빨간 세로선만 덧칠합니다.
프레임마다 다시 그리면 시간만 버리기 때문입니다 — 440장을 만드는 데 **59초** 걸렸습니다.

## 무엇을 보여주는가

* 초록(MuJoCo)과 검정(실물)이 **거의 겹칩니다.** 삼각파 구간에서 차이가 대체로
  **0.2~0.5도**입니다. 화면 왼쪽 아래에 매 순간 그 차이가 숫자로 나옵니다.
* 붉은 선(영상에서 읽은 각도)이 검정과 같이 갑니다. 이것은 **기록이 실제 회전과 맞는다는
  독립 확인**입니다 — 모터가 보고한 숫자만 믿은 것이 아닙니다.
* 앞부분의 빠른 흔들림(0~1.7초)은 진동수를 올려가는 시험이고, 4초 이후가 삼각파입니다.

## 이 영상으로 할 수 없는 말

* **RS03 은 아직 없습니다.** 그 축에도 막대를 붙여야 같은 것을 만들 수 있습니다.
* 영상에서 읽은 각도는 **비스듬히 본 원판**이라 눈금(1.3078배)을 맞춰 쓴 값입니다. 그 눈금은
  기록과 맞춘 것이므로, 붉은 선은 "각도의 절대값"이 아니라 **"회전의 모양이 맞는가"**의
  확인으로만 읽어야 합니다.
* 세기 `kp` 20 · `kd` 1 인 **낮은 세기** 조건입니다. 시뮬레이터에서 쓰는 세기(220)에서는
  되먹임이 물리를 가려서 이 정도로 잘 맞는지 따로 봐야 합니다.
