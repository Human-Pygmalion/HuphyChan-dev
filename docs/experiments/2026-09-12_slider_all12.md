# 2026-09-12 · 화면 슬라이더로 열두 관절 전부 움직이고 데이터를 받음

> 한 줄: **세기 10으로는 다리 무게를 못 이깁니다.** 중력이 걸리는 관절은 시킨 것의
> **24%**, 안 걸리는 관절은 **75%** 만 따라갑니다.

## 무엇을 했나

화면 슬라이더 → UDP → 로봇 프로그램(HUPHY) 제어 루프 → 통신선. 관절마다 지금 자리에서
**±6도 왕복 후 복귀**. 161초, 초당 20번 기록해 3052줄.

| 조건 | 값 |
|---|---|
| 여는 관절 | **12개 전부** |
| 세기 / 감쇠 | kp 10 / kd 1 (설정 파일 값) |
| 가동 범위 | 시뮬레이터 모델 한계, 여유 3도 안쪽 |
| 응답 대기창 | 3밀리초 |
| 발목 | 모터 공간(A/B), 축마다 ±22.75도 **그리고** 발판 자세가 ROM 안 |

토크는 어느 관절도 **1.32 뉴턴미터를 안 넘었습니다** — 세기 10에 오차 6도면
`10 × 0.105 라디안 ≈ 1.05 N·m` 이므로 계산과 맞습니다. 모터 정격(RS04 120, RS03 60)에
비하면 **1%대**입니다. 못 움직인 것은 모터가 약해서가 아니라 **세기를 낮게 준 탓**입니다.

### 오른 무릎이 1%인 이유는 따로 있습니다

지금 **−0.03도**인데 허용 구간이 `[−117, −3]` 입니다 — **이미 구간 밖**입니다. 명령이
−3.00도로 잘리고 오차가 2.97도뿐이라 토크가 더 안 나옵니다. 무릎이 정지마찰에서
풀리는 세기는 벤치 실측으로 **20** 인데 지금 10입니다.

즉 오른 무릎은 **하드스톱(0도)에 거의 붙어 있고, 지금 세기로는 거기서 못 빠져나옵니다.**

## 제가 두 번 틀렸다가 잡은 것

**① 정착오차를 0.08도로 냈습니다 (틀림).** 161초 중 대부분이 **쉬는 구간**(목표=실제)
이라 중앙값이 그쪽에 끌려갔습니다. 원자료를 찍어 보니 목표는 ±6.00까지 갔고 관절은
+1.22/−1.70까지만 갔습니다. **움직이라고 시킨 구간만** 골라 다시 쟀습니다.

**② 응답 대기창을 0으로 두었습니다 (틀림).** 10초만 재고 "0이 최선" 이라 했는데,
90초로 재니 **20초 만에 통신두절로 죽습니다.**

    창        10초 (양다리)     90초 (양다리)
    0 ms      85Hz 무응답 0     **20초 만에 죽음**
    2 ms      66Hz              66.2Hz 버팀
    **3 ms**  68Hz              **68.0Hz 버팀**   <- 채택
    5 ms      57Hz              61.1Hz 버팀

같은 날 5.0 → 0.0 → 3.0 으로 두 번 뒤집혔고, **두 번 다 짧게 재고 결론 낸 것**이
원인이었습니다.

★ 벤치에서 모터 한두 개로 연속 제어가 잘 되던 것은 **왕복이 0.53밀리초**라 여유가
있었기 때문입니다. 12개는 한 주기에 6.28밀리초가 들어 사정이 다릅니다 — 벤치의 감각을
그대로 옮기면 안 됩니다.
