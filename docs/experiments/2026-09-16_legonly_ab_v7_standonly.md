# legonly_ab_v7_standonly — 명령 0만 주고 자립 자세를 학습으로 찾는다 (2026-09-16)

> 약어를 쓰지 않는다. 처음 보는 사람도 읽을 수 있게 쓴다.
> 계보: [[2026-09-14_legonly_ab_v6b_standing_flatfoot]] 의 **유일 변인 후속**.

## §0 왜 이 학습을 하는가

사용자 지시: *"자립하는 각도 학습해서 찾아."*

### §0-1 먼저 한 헛수고 — 고정 각도 탐색

"서는 각도" 를 **상수 세 개**(엉덩이 굽힘 · 무릎 굽힘 · 크랭크 치우침)로 보고, 그것을
직접탐색으로 찾으려 했습니다. 90개 자세를 12초씩 세워 봤고 결과는 이렇습니다.

```
자립 0 / 90
최고: 엉덩이 0.50 · 무릎 8.00 · 크랭크 +10.0 -> 평균 기울기 9.61 deg · 흔들림 폭 33.41 deg
```

얕을수록 덜 흔들리고 깊을수록 더 흔들리다가 너무 깊으면 넘어지는데, **가장 얕은
자세에서도 흔들림 폭 33도**가 남았습니다. 정밀화가 탐색 범위의 구석으로 걸어간 것도
같은 이야기입니다 — 그 방향에 최적점이 없습니다.

**이 접근 자체가 틀렸습니다.** 서는 것은 자세가 아니라 **되먹임**입니다. 기울면 되돌리는
힘이 나와야 하는데, 고정 목표 PD 가 발목에서 내는 복원 강성은 크랭크 kp 22.27 짜리
두 개뿐이고, 필요한 것은 `m·g·h = 23.63 × 9.81 × 0.59 = 137 N·m/rad` 입니다. **6배
모자랍니다.** 그래서 어떤 각도로 세워도 한계주기로 굴러다닙니다.

되먹임을 만드는 것이 정책이고, 그것을 만드는 방법이 학습입니다. **기존 학습 코드에
명령을 0으로 주면 되는 일**이었습니다. 위 탐색은 버립니다 — 도구
(`tools/robot_model/stand_search.py`)와 그 과정에서 나온 숫자만 기록으로 남깁니다.

### §0-2 이 런의 변인

v6b 와 **딱 한 줄** 다릅니다.

```
PYG_REL_STANDING   0.3  ->  1.0        (전 환경을 명령 0 으로)
```

`rel_standing_envs` 는 "몇 퍼센트의 환경을 제자리에 세울 것인가" 입니다. v5 가 0.1,
v6b 가 0.3 이었고, 이번은 **1.0 — 전부** 입니다. 걷기를 아예 안 시키고 서 있기만
시킵니다. 목적이 "자립하는 자세" 하나이므로 걷기 표본에 쓸 이유가 없습니다.

환경 수만 16384 -> **4096** 으로 줄였습니다. v6b 가 같은 GPU 를 쓰고 있어서
(사용 6.8 / 16.3 GB) 그쪽을 밀어내지 않으려는 것이고, 학습 내용과는 무관합니다.

★ 이 런의 **산출물**은 보상 곡선이 아니라 **수렴한 관절 목표 12개**입니다. 그것이

재어 q 목표와 토크를 표로 냅니다.

### §2b 미리 알고 가는 함정

`rel_standing_envs` 는 **커리큘럼 게이트와 구조적으로 상호작용합니다.** 게이트가 쓰는
`error_vel_xy_steady` 는 전 환경 평균인데 서 있는 환경은 가만히 있으면 오차가 0 이라,
정지 비율을 올리면 앞 단계 기준선이 내려가 문턱이 과하게 좁아집니다 (v6b 에서 실측:
기준선 0.2131 → 0.1679, 비율 1.273 으로 졸업 실패). **1.0 은 그 극단**이므로 게이트가
아예 안 열릴 수 있습니다. 그때는 `--gate-err-ratio` 를 올리거나 1단계 상한까지
그대로 진행합니다 — 걷기를 안 시키는 런이라 커리큘럼 자체가 덜 중요합니다.
