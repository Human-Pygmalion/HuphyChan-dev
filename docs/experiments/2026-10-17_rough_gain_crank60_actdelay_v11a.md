## §0 왜 하는가

- 묶음 시험은 게인 배율 0.5 에서 8/8 을 버텼지만 제자리 회전이 45.3 % 에서 23.4 % 로 내려갔다 ([[2026-10-14_rough_box_trial_v11a]] §12).
- 팔 A 는 크랭크 게인만 바꿨다. 제자리 회전은 53.5 % 로 유지했지만 게인 배율 0.5 에서는 1/8 만 버텼다 ([[2026-10-15_rough_gain_crank60_v11a]] §12).
- 따라서 회전 손실의 원인은 크랭크가 아니다. 남은 후보는 지연과 게인 무작위화이다.
- 이 팔은 명령 지연 무작위화 하나만 팔 A 에 더한다. 지연은 정책이 보는 관절 반응을 느리게 만든다. 그래서 회전 같은 큰 동작의 추종을 해칠 수 있다.
- 이 팔은 방향을 예측하지 않는다. 지연이 게인 배율 0.5 의 내성을 바꾸는지 모르기 때문이다. 팔 C 와 비교해 두 원인을 가른다.

## §1 팔 A 에서 바뀐 것

팔 A 와 **같은 것**: 시작 체크포인트(평지 v11a `model_29998.pt` 의 배우만), 씨앗 43, 12,000 회, 환경 4,096개, 기록 방식 tensorboard, 지형, 보상 전부, 명령 상자, 관절 범위, 로봇 모델, 크랭크 게인 60/2.7, 팔 A 의 `PYG_*` 환경 변수 전부, 같은 발사기.

| 변경 | 환경 변수 | 팔 A | 팔 D | 이유 |
|---|---|---|---|---|
| 명령 지연 무작위화 | `PYG_ACTION_DELAY` | 없음 | **`1.0`** | 비율 d 의 최댓값이 1.0 이다. 최대 1 정책 스텝(20 ms)이다. 묶음 시험과 같은 값이다. |

- 무작위화 곡선: 최댓값이 2,000 회에서 8,000 회 사이에 0 에서 1.0 으로 오른다 (`action_delay_max`).
- 구현 위치: `mujoco-sim/mjlab/src/mjlab/tasks/velocity/config/pygmalion/delayed_action.py` 와 같은 폴더 `env_cfgs.py` 의 `PYG_ACTION_DELAY` 블록. 행동 항목이 지연 항목으로 바뀌고, 기존 필드는 그대로 옮겨진다.
- 행동 잡음(`PYG_ACTION_NOISE`)은 켜지 않는다. 잡음 필드는 0 이다.
- 게인 무작위화, 밀기 완화, 엔코더 확대는 켜지 않는다 (`PYG_PD_GAIN_DR`, `PYG_PUSH_SOFT`, `PYG_ENC_BIAS_MAX` 모두 없음).

**발사 전 실증** (`mujoco-sim/mjlab/analysis/verify_gain_flags.py --arms ...`, 환경 2개, CPU, 원자료 `analysis/out/verify_cd/`):
- 팔 D 의 환경 설정은 팔 A 와 네 줄 다르다. 모두 추가된 줄이다. 삭제된 줄은 없다.
- 네 줄은 행동 항목의 `max_delay: 1.0`, `noise: 0.0` 과 무작위화 곡선의 `action_delay_max: 1.0`, `action_noise_max: 0.0` 이다.
- 만들어진 액추에이터의 값은 팔 A 와 같다. 크랭크 네 개 60/2.7, 엉덩이 비틀기 150/6, 엉덩이 앞뒤·좌우 150/6, 무릎 220/6.
- 환경 64개로 4회 짧은 학습을 통과했다. 런 이름은 `smoke_cd_actdelay_v11a` 이다. 폴더의 `params/env.yaml` 에 `max_delay: 1.0` 이 있다.

> 주의: 이 런도 평지 v11a 2단계 최종 정책에서 **배우만 이어 받아** 시작한다. 초반 수백 회의 보상·넘어짐이 팔 A 보다 나빠도 그것만으로 실패로 보지 않는다. 판정은 §1c 의 완주 뒤 측정으로만 한다.

## §1c 사전 등록한 판정 기준 (팔 C 와 팔 D 에 같은 기준을 적용한다)

완주 뒤 아래를 순서대로 확인한다. 비교 대상은 팔 A 이다.

1. 마지막 200 회 평균 `fell_over` 와 `low_base` 가 팔 A 보다 높지 않다 (팔 A 는 0.0134 / 1.470).
2. 제자리 회전: 씨앗 8 개의 중앙값이 팔 A 의 53.5 % 에서 10 점을 뺀 값 이상이다. 반대 방향 회전은 팔 A 의 3/64 에 3 을 더한 값 이하이다.
3. 서 있는 동안 흘러간 거리가 0.5 m 이하이다.
4. 실기 조건 시뮬레이터(`tools/sim2real/real_condition_sim.py --crank-kp 60 --crank-kd 2.7`, 14 조건, 조건마다 8 번): 게인 배율 0.5 에서 팔 A 의 1/8 보다 잘 버틴다. 팔 C 의 가설은 6/8 이상이다. 팔 D 는 방향을 예측하지 않는다. 실제 타이밍 조건은 8/8 이다.
5. 직진 1.2 m/s 명령에서 걷는 동안 방향각 변화율(`tools/robot_gains/heading_drift_probe.py`)을 팔 A 의 +4.48 도/초와 비교한다. 임계값은 없고 값을 기록한다.

- **평가에서 명령 지연 무작위화를 끄는 방식은 새로 만든 것이다.** 팔 C 의 게인 무작위화를 끄는 방식과 같은 틀이다. 이유와 확인은 §3c 에 있다. 확인 도구 `tools/sim2real/action_delay_eval_check.py` 는 이번에 새로 만들었다.

- 중앙처리장치는 같은 컴퓨터에서 다른 사용자의 시각화 프로그램(rviz2, 약 3.4 코어)과 나눠 썼다. 측정은 `nice -n 10` 으로 최대 3 개를 동시에 돌렸다. 부하 평균은 약 25 였다. 제자리 회전 한 건이 약 15 분 걸렸다.
