## 3. 무작위화 대조·배포 경로·기록 건강 (`docs/sim2real/2026-10-30_union49999_dr_coverage_and_risks.md`, 감사 전)

### 3-1. 해결된 것

- **떨림 해결을 숫자로 확인했다.** 서 있을 때 3~8 Hz 대역 힘이 0.066·0.036 deg² 이다. 10-21 진동 확인 기록은 0.62 deg² 였다 (약 10~17 배 감소). 정책 간격 중앙 20.006 ms, 최대 22.3 ms. 늦거나 잃은 응답 0 개 (109,788 개 중).
- **배포 계약이 맞다.** 해시 일치. 기록된 입력을 정책에 다시 넣으면 기록된 행동과 최대 3.4e-5 차이. 게인·기본 자세·배율·자르기 일치. 엉덩이 좌우 목표값이 안쪽 한계에 잘린 적은 없다 (안쪽 최대 8.7°, 가드 16.5°).

### 3-2. 발 간격 (실기 관절각의 순기구학, 발목 중심 사이 거리)

| 구간 | 거리 |
|---|--:|
| 학습 기본 자세 | 24.7 cm |
| 시작 직후 서기 | 27.0~27.3 cm |
| 첫 걸음 뒤 서기 | **22.0~22.3 cm** (다시 넓어지지 않는다) |
| 걷기 중 | 중앙 **21.7~22.2 cm**, 최소 **14.2 cm** |

### 3-3. 학습 쪽에서 찾은 원인 후보

1. **발 간격을 지키는 보상이 없다.** 발 사이 거리를 직접 벌하는 항이 없다. 좁아지는 쪽을 막는 것은 자기 충돌 벌점 하나이다. 그 벌점은 다리 하나가 안쪽으로 약 4.6° 들어가야 시작한다. 자세 보상의 엉덩이 좌우 허용 폭은 걷기 중 0.4 rad (23°) 로 넓다.
2. **시작 자세 외란이 안쪽으로 치우쳐 있다.** 무작위화의 "엉덩이 좌우 벌림 외란" `U(-0.10, 0.06)` rad 은 스쿼트 과제에서 그대로 가져왔다. 스쿼트의 기본 자세는 엉덩이 좌우가 바깥으로 0.05 rad 이다. 걷기의 기본 자세는 0 이다. 그래서 걷기에서는 이 범위가 **안쪽으로 치우친다.** 벌림 외란이 걸린 시작의 6.1 % (전체의 3.0 %) 는 두 다리가 닿은 채로 시작한다. 정책은 좁은 자세에서 시작하는 경험을 많이 했고, 좁은 자세를 벌할 항은 없었다.

### 3-4. 무작위화가 덮지 못한 것

| 항목 | 실기 | 학습 무작위화 | 판정 |
|---|---|---|---|
| 관절 영점 | 보정 파일이 아직 자리표시자 (모두 0). 재보정 뒤 잔여 1~5° | ±0.015 rad (±0.86°) | **덮지 못함** |
| IMU 값 멈춤 | 기록 행의 5~7.5 %, 최장 0.64 초 | 없음 | **덮지 못함** |
| 원격 조작 명령 | 패드 입력이 계단처럼 바뀜, 0.5 초 감시 장치가 명령을 0 으로 끊음 | 3~8 초마다 무작위로 바꿈, 계단 변화만 | 일부 |
| 명령 범위 | HUPHY 계약에 속도 명령 범위가 없다 (범위 밖 명령이 그대로 들어감) | vx −1~2, wz −1~1 | 위험 |
| 실물 질량·발 질량 | 모름 (모델 발 0.618 kg, 실측 발판 0.182 kg) | 몸통 추가 −1~+8 kg, 링크 ±10 % | 모름 |
| 발목 연결부 마찰 | 모름 | 0~0.5 N·m (새로 추가) | 일부 |

### 3-5. 그 밖의 위험

- **직진 중 오른쪽 쏠림이 남았다.** vx > 0.1, |wz| < 0.05 구간의 방향 변화율 −4.6 °/s (8 구간 중 7 구간 오른쪽). 37400 시뮬레이터 기준은 −1.8 °/s 였다. 회전 명령 추종 이득 0.57~0.62 (37400 은 0.58). 방향 보상은 이 쏠림을 약 1.3 % 만 벌한다.
- **오른 발목 크랭크 A 가 목표를 거의 따라가지 못한다.** 관절 1.2° 대 목표 6.7°, 결맞음 0.12~0.17 (왼쪽 0.79~0.91). 177 §11 의 "크랭크 A 이득 절반" 과 같은 쪽이고 더 심하다. **하드웨어 점검 대상이다.**
- 엉덩이 앞뒤 지연 약 95 ms (177 §11 의 약 80 ms 와 비슷).
- **재현 위험:** 가지 끝의 자세 보상 무게가 0.5 이다 (커밋 `981a245`). 49999 의 `env.yaml` 은 1.0 이다. 가지 끝에서 다시 학습하면 다른 정책이 된다.

## 4. 판정 — 좁은 걸음은 주로 정책 자체의 성질이고, 서 있을 때의 추가 좁아짐은 실기에만 있다

근거: `docs/sim2real/2026-10-30_union49999_stance_width.md` (같은 정책·같은 명령 순서로 시뮬레이터 재생, 단일 변경 시험). 부호는 모델 축과 순기구학으로 확인했다: 오른쪽 hip_roll + 와 왼쪽 − 가 바깥 벌림이다 (§2 의 가정이 맞다).

### 4-1. 숫자 (기록 1, 발 중심 사이 좌우 거리, cm)

| 구간 | 실기 | 시뮬레이터 (무작위화 끔) | 시뮬레이터 (학습 무작위화) |
|---|--:|--:|--:|
| 정책이 지시하는 폭 | 39.9 | 38.7 | 39.4 |
| 실제 폭, 전체 | 22.5 | 25.8 | 25.1 |
| 걷기 | 21.9 | 23.5 | 23.0 |
| 걸음 폭 (두 발이 앞뒤로 스칠 때) | **22.4** | **22.1** | **22.7** |
| 서기 | 22.9 | 27.4 | 27.0 |
| 5 초 넘게 선 뒤 | **22.5** | **29.1** | — |

학습 기본 자세의 폭은 24.7 cm 이다.

### 4-2. 판정

1. **걸을 때 좁은 것은 정책의 성질이다.** 같은 명령으로 시뮬레이터도 걸음 폭 22.1 cm 로 걷는다. 실기 22.4 cm 와 같다. 기본 자세 24.7 cm 보다 좁다. 시뮬레이터는 이 폭으로 넘어지지 않는다.
2. **정책은 넓게 지시하지만 지지 다리가 버티지 못한다.** 정책은 39~40 cm 를 지시한다. 외다리 지지 때 hip_roll 은 약 18 N·m 를 내야 한다. Kp 135 N·m/rad 에서 이 토크는 약 8° 의 위치 오차이다. 그래서 목표 +8.6° 에도 관절은 +0.6° 에 머문다. 이 평형은 시뮬레이터에도 있다 (목표−측정 +3.9 / −4.1°). 정책은 이 평형에서 학습되었다. 보상에는 폭을 지키는 항이 없다 (§3-3).
3. **실기에만 있는 차이는 서 있을 때이다.** 시뮬레이터의 발은 서 있는 동안 바깥으로 벌어진다 (29.1 cm). 실기의 발은 22.5 cm 에 머문다. 서기 폭 차이는 4.5~6.5 cm 이다. 실기 목표−측정도 서기 때 가장 크다 (오른 +5.5° 대 시뮬레이터 +1.7°).
4. **실기의 추가 좁아짐을 만드는 단일 조건은 둘이다.** hip_roll 의 실제 강성이 설정의 약 0.7 배이거나, 몸통이 모델보다 약 4~6 kg 무겁다. 둘 다 시뮬레이터를 폭 21~23 cm 로 만든다. 마찰, 발 마찰, 토크 한계, IMU 롤 장착각은 폭을 바꾸지 못했다. 기록만으로는 둘을 가를 수 없다. 둘 다 크랭크 오차는 실기보다 크게 만든다. 그러므로 어느 하나가 전부를 설명하지는 않는다.
5. **영점 오차는 기록에 보이지 않는 좁아짐을 만든다.** hip_roll 영점이 안쪽으로 2° 어긋나면 기록의 각도와 폭은 그대로이다. 실제 폭은 25.4 cm 에서 20.1 cm 로 줄어든다 (4° 면 15.0 cm). 실기 보정 파일은 아직 자리표시자이다 (§3-4). 그러므로 **실기 폭 22.5 cm 는 상한일 수 있다.**
6. **좌우 비대칭은 실기에만 있다.** 실기 목표−측정은 오른 +6.5° / 왼 −4.3° 이다. 시뮬레이터는 +3.9 / −4.1° 로 대칭이다. 어느 단일 변경도 이 비대칭을 만들지 못했다. 후보: 오른쪽 영점, 질량 중심의 좌우 치우침, 오른쪽 부품 마찰. 오른 크랭크 A 의 추종 불량(§3-5)과 오른쪽 쏠림(§3-5)도 같은 오른쪽이다.
7. **좁은 폭만으로 실기 불안정을 다 설명할 수는 없다.** 시뮬레이터는 같은 걸음 폭으로 넘어지지 않는다. 실기에는 여유를 줄이는 것이 더 있다: 서 있을 때 더 좁은 폭, 영점 오차 가능성, 오른 크랭크 A, IMU 값 멈춤, 모르는 질량. 기록에는 접촉 신호와 토크가 없어서 넘어짐 직전의 원인을 직접 볼 수 없다.

시작 외란 부호도 코드로 다시 확인했다. `add_hip_roll_reset_spread` 는 오른쪽에 `+spread`, 왼쪽에 `−spread` 를 더한다. 범위 `(-0.10, 0.06)` 의 평균은 −0.02 rad 이다. 그러므로 평균이 안쪽이다 (안쪽 최대 5.7°, 바깥 최대 3.4°).

### 4-4. 모터 전류로 확인한 것 (`docs/sim2real/2026-10-30_union49999_kp_and_zero_check.md`, 기록 2)

1. **모터의 강성은 설정값과 같다.** 전류(iq)로 구한 실효 Kp 는 오른 131 / 왼 132 N·m/rad (설정 135) 이다. 비율은 0.99 / 1.08, R² 0.98 이다. 그러므로 "모터 Kp ×0.7" 후보는 모터 쪽에서 기각한다. 시뮬레이터의 Kp ×0.7 은 "다리가 좌우로 무른 것" 을 흉내 낸 대리 변수로만 본다.
2. **hip_roll 영점 오차는 서기 좁아짐의 원인이 아니다.** 서 있을 때 두 발바닥의 대칭 기울기는 +0.06° (구간 사이 ±0.3°) 이다. 안쪽 2° 영점 오차라면 약 −2° 가 보여야 한다. 남을 수 있는 크기(0.4°)는 폭 약 1.2 cm 이다. 단, 서로 보상하는 hip_roll·발목 쌍과 hip_yaw 영점은 이 검사로 보이지 않는다.
3. **서 있을 때 hip_roll 토크가 시뮬레이터의 2.2~3.9 배이다.** 실기 +10.9 / −10.6 N·m, 시뮬레이터 +2.8 / −4.9 N·m 이다. 외다리 지지 토크는 같다 (27.2 대 29.5 N·m). 외다리 토크가 같으므로 "몸통 +4~6 kg" 후보는 약해진다.
4. **새 발견: 걷기 외다리 지지 때 지지 발바닥이 바깥 가장자리가 들린 채 3.9° (오른) / 4.8° (왼) 기울어 있다.** 시뮬레이터는 0.08° 이다. IMU 는 원인이 아니다 (자이로 적분과 5 % 안에서 맞음). 이 기울기는 엔코더 뒤의 무른 곳(발목 크랭크 연결부, 발목 베어링, 발바닥)이나 발이 실제로 안쪽 가장자리로 딛는 것을 뜻한다. 확인되지 않았다.

**판정 수정.** §4-2 의 4번에서 "강성 ×0.7 또는 몸통 +4~6 kg" 이라고 썼다. 전류 결과로 모터 강성은 기각하고, 질량은 약해졌다. 남은 설명은 둘이다.
- (가) **실기는 서 있을 때 발이 미끄러지지 않는다.** → **시험 결과 지지되지 않음** (아래 4-5). 정책은 서 있을 때 다리를 바깥으로 민다. 시뮬레이터에서는 발이 조금씩 미끄러져 폭이 29 cm 까지 벌어진다. 실기에서는 발이 버티고, 그 힘이 토크(±11 N·m)로 남는다. 이 설명은 "실기 서기 폭이 그대로" 와 "실기 서기 토크가 2~4 배" 를 함께 설명한다. 시뮬레이터 접촉 모형의 미끄러짐(소프트 접촉의 크리프)을 시험 중이다 (`docs/sim2real/2026-10-30_union49999_sim_contact_creep.md`).
- (나) **지지 다리가 엔코더 뒤에서 좌우로 무르다.** 발바닥 기울기 4~5° 가 그 흔적일 수 있다.

### 4-5. 시뮬레이터 접촉 미끄러짐 시험 (`docs/sim2real/2026-10-30_union49999_sim_contact_creep.md`)

- 시뮬레이터의 발은 서 있는 동안 실제로 미끄러진다 (왼발 약 3 mm/s, 10 초에 3 cm). 발을 들지 않는다.
- 그러나 접촉을 단단하게 바꿔도 (원뿔 마찰 모형, impratio 10·100) 서기 폭은 28.8~29.5 cm 로 거의 같다. 서기 hip_roll 토크도 ±3~5 N·m 에 머문다 (실기 ±11).
- 시뮬레이터는 서기 시작 1 초 만에 이미 26~27 cm 이다. 미끄러짐은 그 위에 1.3~3.7 cm 만 더한다.
- `noslip` 은 학습에 쓴 `mujoco_warp` 에서 지원하지 않는다. 학습도 이 설정 없이 했다.
- **판정: "시뮬레이터만 벌어진다" 는 설명은 일부(최대 3.7 cm)만 맞다.** 실기와 시뮬레이터의 서기 차이 대부분은 아직 설명하지 못했다. 남은 후보는 멈출 때 마지막 걸음이 어디에 놓이는지, 실기 발바닥의 마찰, 엔코더 뒤의 무름(§4-4 의 발바닥 기울기 4~5°) 이다. 모두 실기 측정이 필요하다 (§5-1).

### 4-6. 최종 정리

- **걷기의 좁은 폭(약 22 cm)은 정책의 성질이다.** 실기와 시뮬레이터가 같다. 해결은 다음 학습의 발 간격 보상과 시작 외란 수정이다 (§5-3).
- **서 있을 때 실기만 더 좁다 (22.5 대 27~29 cm).** 모터 강성, hip_roll 영점, 시뮬레이터 접촉 미끄러짐은 주원인이 아니다. 원인은 실기 측정으로 가린다.
- **바로 할 수 있는 처방:** hip_roll Kp ×1.2 부터 (§5-2).

### 4-3. 학습과 배포의 초기 자세값 대조 (사용자 질문, 2026-10-30)

**숫자로 적힌 기본 자세는 세 곳에서 같다.**

| 출처 | hip_pitch R / L | hip_roll R / L | 무릎 R / L | 크랭크 A R / L |
|---|---|---|---|---|
| 학습 `env.yaml` `init_state.joint_pos` | −0.175 / +0.175 | 0 / 0 (적지 않음 = 0) | +0.35 / −0.35 | +0.14395 / −0.14388 |
| 배포 `deploy.yaml` `default_position_rad` | 같음 | 0 / 0 | 같음 | 같음 |
| HUPHY `deploy_contract.json` `offset_rad` | 같음 (차이 < 1e-6 rad) | 0 / 0 | 같음 | 같음 |

- HUPHY 는 이 값을 세 곳에 쓴다: 목표의 기준점, 관측 관절각의 기준점, 정책 시작 전 자세 (`run.py` 의 `approach`). 세 곳 모두 같은 값을 쓴다.
- 기록 첫 행에서 hip_roll 은 오른 −0.05° / 왼 −0.08° (기록 2: −0.71° / −0.67°) 이다. 로봇은 기본 자세에서 정책을 시작했다.
- 관측 `obs/q` 는 `pos − 기본 자세` (rad) 와 맞는다. 기록 재생도 3e-5 안에서 맞는다 (§3-1).

**숫자는 같지만, 그 숫자가 실물에서 어느 자세인지는 확인되지 않았다.**

- HUPHY 1.0 보정 파일(`config/calibration/{left,right}_leg_v1.0.json`)은 모든 관절이 `offset_deg = 0`, `zero_reference = "0"` 이다. 파일의 메모는 "아직 아무것도 재기 전" 이다.
- 그러므로 관절 0° 는 모터에 저장된 기계 영점이다. 그 영점을 어느 자세에서 잡았는지 기록이 없다.
- `limits_deg` 도 실측이 아니다. 학습 모형의 가동 범위를 옮겨 적었다 (HUPHY 커밋 `b1ac519`).
- 따라서 "로봇이 기본 자세에 있다" 는 말은 "모터 각도가 기본 자세의 숫자와 같다" 는 뜻이다. 실제 다리 각도가 시뮬레이터의 기본 자세와 같은지는 모른다.
- 영향: hip_roll 영점이 안쪽으로 2° 어긋나면, 기록은 바뀌지 않고 실제 폭만 약 5 cm 줄어든다 (§4-2 의 5번). 다른 관절(크랭크, 무릎)의 영점 오차는 발바닥 기울기와 높이를 바꾼다.
- 확인 방법: (1) §5-1 의 줄자 시험, (2) 기본 자세에서 다리를 정면·측면으로 사진 찍어 각도를 잼, (3) 기록에서 두 발바닥의 높이 차와 기울기 검사 (진행 중, `docs/sim2real/2026-10-30_union49999_kp_and_zero_check.md`).

### 5-2. 재학습 없이 배포에서 바로 할 수 있는 것 (시뮬레이터 시험 결과)

근거: `docs/sim2real/2026-10-30_union49999_deploy_fix_sim.md`. 기록 1 의 9~29 초, 환경 4 개, 무작위화 끔. 같은 구간의 실기 폭은 22.0 cm 이다. 아래 값은 전체 폭 / 걷기 폭 [cm] 과 넘어짐이다.

| 처방 | 조건 "강성 ×0.7" (처방 없음 22.7 / 21.2) | 조건 "몸통 +6 kg" (처방 없음 20.5 / 19.3) | 무작위화 끈 기준 (25.4 / 23.5) |
|---|---|---|---|
| hip_roll Kp ×1.2 | — | 24.1 / 22.0, 0/4 | 26.6 / 24.4, 0/4 |
| hip_roll Kp ×1.4 | 25.3 / 23.4 (×1.43), 0/4 | **25.7 / 23.3, 0/4** (토크 최대 98 / 120 N·m) | 27.3 / 25.6, 0/4 |
| 바깥 목표 고정값 1° | 24.5 / 23.2, 0/4 | 21.0 / 20.8, 0/4 | 27.6 / 25.5, 0/4 |
| 바깥 목표 고정값 2° | 26.4 / 25.3, 0/4 | 22.2 / 22.2, 0/4 | 30.5 / 28.1, 0/4 |
| 바깥 목표 고정값 3° | 29.2 / 28.1, 0/4 | 23.5 / 23.9, **4/4 넘어짐** (hip_roll 120 N·m 포화) | 33.1 / 30.7, 0/4 |

- **hip_roll Kp 를 1.4 배(135 → 약 190 N·m/rad)로 올리는 처방이 두 조건 모두에서 폭을 기준 수준(약 25 cm)으로 돌린다.** 넘어짐은 없다. 무작위화를 끈 기준 로봇에서도 넘어지지 않는다.
- 바깥 목표 고정값은 "강성 ×0.7" 조건에서만 듣는다. "몸통 +6 kg" 조건에서는 정책이 고정값의 일부를 되돌린다. 3° 에서는 hip_roll 토크가 한계에 닿아 넘어진다. **원인이 확정되기 전에는 쓰지 않는다.**
- 권고 순서: hip_roll Kp ×1.2 → ×1.4 로 올린다. 두 hip_roll 만 바꾼다. 다른 관절은 바꾸지 않는다. 처음에는 줄로 매달고 시험한다.
- 한계: 시뮬레이터 시험은 지연과 잡음이 없다. 실기에서 강성을 올리면 떨림이 다시 생길 수 있다 (37400 의 5 Hz 떨림, 177 §4). 시험 때 3~8 Hz 대역 힘을 §3-1 의 값(0.04~0.07 deg²)과 비교한다. 정책은 Kp ±20 % 로 학습되었다. ×1.4 는 학습 범위 밖이다. 실제 강성이 ×0.7 이라면 ×1.4 를 곱한 결과는 ×1.0 이 되어 학습 범위 안으로 돌아온다.
- 전류 기록으로 확인한 결과, 모터 강성은 설정값과 같다 (§4-4). 그러므로 Kp ×1.4 는 실제로 학습 범위(±20 %) 밖의 강성이다. 실기 시험은 ×1.2 (학습 범위 끝)에서 시작한다.

### 5-3. 다음 학습 (정책 제작자에게 전달)

1. **발 간격 보상을 넣는다.** 몸통 좌표계에서 두 발의 좌우 거리에 아래 한계를 둔다. 아래 한계는 기본 자세 폭 근처(약 0.22~0.25 m)로 둔다. humanoid-gym 의 `feet_distance` 항과 같은 형태이다. 무릎 사이 거리 항(`knee_distance`)도 같이 쓴다.
2. **시작 외란을 걷기 기본 자세에 맞춘다.** `reset_hip_spread` 범위를 대칭(예: `(-0.06, 0.06)`) 이나 바깥쪽으로 바꾼다. 지금 범위는 스쿼트 기본 자세(바깥 0.05 rad)에 맞춘 값이다.
3. **무작위화 범위를 실기 후보에 맞춘다.**
   - hip_roll 강성: 지금 Kp ±20 % 는 ×0.7 을 덮지 못한다. 범위를 ×0.6~1.2 로 넓힌다. 또는 모터 힘 범위를 낮은 쪽으로 넓힌다.
   - 영점 오차: 지금은 목표에만 ±0.86° 를 더하고 관측에는 더하지 않는다 (`biased=False`). 실기 영점 오차는 관측에도 들어간다. 관측에 ±2~3° 를 더한다.
   - IMU 값 멈춤(최장 0.64 초)을 넣는다.
   - 몸통 질량: 지금 범위(+8 kg 까지)는 후보를 덮는다. 다만 무작위화를 끈 시뮬레이터는 +8 kg 에서 7~11 초 안에 넘어진다. 무거운 쪽에서 정책이 버티는지 따로 확인한다.
4. **재현 위험을 없앤다.** 가지 끝의 자세 보상 무게(0.5)를 49999 의 `env.yaml` 값(1.0)과 맞추거나, 바꾼 이유를 적는다.

- 관절 속도와 토크(전류)를 기록한다. 지금은 넘어짐 원인을 기록으로 볼 수 없다.
