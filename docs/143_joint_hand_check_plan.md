# 손으로 관절을 움직여 모형과 맞는지 보는 절차 (2026-09-14 준비)

사용자 지시: *"이제 각 관절들 실제 움직여보고, MJCF 상 조인트 움직임과 같은지,
한계범위에 잘 맞는지 검토해 보려 해. 준비해줘."*

---

## §0 지금 확인해야 할 것은 **부호와 영점** 하나뿐입니다

한계 범위는 **이미 맞는 것으로 확인됐습니다.** 로봇이 실제로 내보낸 텔레메트리의
`lo`/`hi` 와 최종 MJCF 를 맞대 보면 **여유 3도만큼만** 차이납니다.

| 관절 | 로봇 설정 (여유 3도 뺀 값) | 최종 MJCF | 맞나 |
|---|---|---|---|
| 왼 엉덩이앞뒤 | −22.0 ~ +117.0 | −25 ~ +120 | ✅ |
| 왼 엉덩이좌우 | −82.0 ~ +22.0 | −85 ~ +25 | ✅ |
| 왼 엉덩이회전 | −42.0 ~ +42.0 | −45 ~ +45 | ✅ |
| 왼 무릎 | −117.0 ~ −3.0 | −120 ~ 0 | ✅ |
| 왼 크랭크 A·B | −65.75 ~ +65.75 | −68.75 ~ +68.75 | ✅ |
| 오른쪽 여섯 개 | 위의 좌우 뒤집은 값 | 뒤집은 값 | ✅ |

**아직 한 번도 확인 안 된 것**은 `joint_map_huphy.json` 의 `sign` 과 `offset_rad`
입니다. 지금 전부 `sign: 1, offset: 0` 이고 `side_mapping_verified: false` 입니다.
즉 **모터가 도는 방향과 영점이 모형과 같은지 아무도 재 본 적이 없습니다.**
이번에 손으로 움직여 보는 것이 바로 그 측정입니다.

## §1 ★ 함정 — 좌우가 **관절마다 다르게** 뒤집혀 있습니다

모형에서 각 관절에 +10도를 넣고 발이 어디로 가는지 실제로 재 봤습니다.

| 관절 | MJCF 범위 [도] | 회전축 | **+10도를 넣으면 발이** |
|---|---|---|---|
| 왼 엉덩이앞뒤 | −25 ~ +120 | −y | **앞으로** 150 mm |
| 오른 엉덩이앞뒤 | −120 ~ +25 | **+y** | **뒤로** 148 mm |
| 왼 엉덩이좌우 | −85 ~ +25 | −x | **오른쪽** 149 mm |
| 오른 엉덩이좌우 | −25 ~ +85 | **−x (같음)** | **오른쪽** 149 mm |
| 왼 엉덩이회전 | −45 ~ +45 | +z | 오른쪽 13 mm |
| 오른 엉덩이회전 | −45 ~ +45 | **+z (같음)** | 오른쪽 13 mm |
| 왼 무릎 | −120 ~ 0 | −y | **앞으로** 86 mm |
| 오른 무릎 | 0 ~ +120 | **+y** | **뒤로** 85 mm |

**엉덩이앞뒤와 무릎은 좌우가 뒤집혀 있고, 엉덩이좌우와 엉덩이회전은 안 뒤집혀
있습니다.** 그래서

* 두 무릎을 **똑같이** 굽히면 화면 숫자는 **반대 부호**로 갑니다 (왼쪽 음수, 오른쪽 양수).
* 두 다리를 **똑같이** 바깥으로 벌리면 엉덩이좌우 숫자는 **같은 방향**으로 갑니다.

이걸 모르고 보면 멀쩡한 것을 "부호가 틀렸다" 고 판정하게 됩니다.

## §2 발목 — 크랭크 두 개가 발판 하나를 움직입니다

크랭크에 +15도를 넣었을 때 발판이 서는 각도(모형에서 실제 측정):

| 크랭크 | 발판 숙임 변화 | 발판 기울임 변화 |
|---|--:|--:|
| 왼 A | −8.99도 | −11.12도 |
| 왼 B | +8.60도 | −10.18도 |
| 오른 A | +8.86도 | +10.11도 |
| 오른 B | −8.52도 | +10.88도 |

읽는 법:

* **A 와 B 를 같은 방향으로** 돌리면 숙임은 거의 상쇄되고 **기울임만** 남습니다
  (왼발은 +A+B 가 기울임 −21도, 오른발은 +21도 — 좌우 반대).
* **A 와 B 를 반대로** 돌리면 **숙임만** 남습니다.
* 그러니 발목은 크랭크 하나씩 보지 말고 **발판이 어디로 서는지**로 확인해야 합니다.

## §3 절차

**전제: 모터에 힘이 들어가지 않습니다.** 관찰 모드는 켜기(0xFC)를 한 번도 안 보내고
게인·토크 0 프레임으로 상태만 읽습니다. 그래서 손으로 움직일 수 있습니다.

1. **48 V 전원을 넣습니다.** (2026-09-14 현재 모터 12개가 통신에 무응답 —
   [[2026-09-14_motor_bus_silent]]. 이것이 안 풀리면 아래를 시작할 수 없습니다.)
2. 통신선 확인 — 이미 올라가 있습니다 (`can0`·`can1` UP). 재부팅했다면
   `bash ~/System_ID/can_up.sh`.
3. 응답 확인 — `huphy.scripts.commission ... scan` 이 여섯 개 다 값을 내야 합니다.
4. **관찰 모드 시작** (로봇에서, 명령 한 줄):

   ```
   cd ~/System_ID && PYTHONPATH=$HOME/HUPHY/src setsid nohup python3 -u huphy_live.py \
     --config $HOME/HUPHY/config/robot.yaml --robot --observe \
     --state-to 10.8.0.16:9871 --state-hz 20 > /tmp/observe.log 2>&1 &
   ```
5. **화면** — `http://192.168.20.177:8096/` (`huphy_viser`, 읽기 전용). 관절마다
   `q / tgt / tau` 가 뜨고 3차원 로봇이 실물을 따라 움직입니다.
6. **카메라** — `http://10.8.0.17:8099/` 로 옆에서 보면서 합니다.
7. 관절 하나씩 §4 대로 움직이고, 화면 숫자를 §1·§2 의 기댓값과 맞대 봅니다.

## §3b ★ 첫 결과 — **무릎 영점이 모형과 어긋나 있다** (2026-09-15)

3차원 화면에 실물을 연결하자마자(초당 20회, 지연 13 ms, 브리지 오류 0) **손을 대기도 전에**
하나가 드러났습니다.

| 관절 | 실물 | 화면(모형) | 차 |
|---|--:|--:|--:|
| 왼 엉덩이좌우 | +8.39° | +8.41° | **+0.02** |
| 왼 엉덩이회전 | −2.14° | −2.16° | **−0.02** |
| 오른 엉덩이앞뒤 | −4.10° | −4.10° | **0.00** |
| **왼 무릎** | **+7.53°** | **0.00°** | **−7.53** ← 잘림 |
| **오른 무릎** | **+2.58°** | **0.00°** | **−2.58** ← 잘림 |
| 왼 크랭크 A | −6.41° | −9.83° | −3.42 |
| 왼 엉덩이앞뒤 | +1.15° | −1.13° | −2.28 |

뷰어가 세는 값:

```
range_violations: L_knee_joint 1647회
replay_clamp:     L_knee 1026회 · R_knee 1026회   (지금도 잘리는 중)
마지막 위반: L_knee value +0.1314 rad, limit [-2.0944, 0.0], over_by +0.1314
```

**읽는 법**: 모형의 왼 무릎 범위는 −120°~0° 라 **양수가 존재할 수 없습니다.** 그런데 실물이
+7.53° 를 읽습니다. 로봇 무릎은 지금 거의 곧게 펴져 있으니, **엔코더의 0 이 모형의 0(완전히
편 상태)보다 몇 도 넘어가 있다**는 뜻입니다. 크기가 2~8° 로 작아 **부호가 뒤집힌 것은
아닙니다** — `offset_rad` 로 맞출 문제입니다.

엉덩이좌우·회전은 0.02° 안에서 맞으므로 **연결과 대응표 자체는 옳습니다.** 어긋난 것은
무릎(양쪽)·크랭크 A·엉덩이앞뒤(왼쪽) 넷입니다.

**아직 부호는 확인 못 했습니다** — 그러려면 §4 대로 손으로 움직여 봐야 합니다.

## §4 관절별 확인표 (열두 개)

각 관절마다 **세 가지**를 봅니다.

| 무엇 | 어떻게 |
|---|---|
| ① 방향 | 손으로 한쪽으로 움직였을 때 화면 숫자가 §1 의 방향으로 가는가 |
| ② 영점 | 다리를 곧게 편 자세에서 숫자가 0 근처인가 |
| ③ 한계 | 기구가 더 안 가는 곳까지 밀었을 때 그 숫자가 §0 표의 끝값과 맞는가 |

| # | 관절 | 손으로 할 일 | 화면에서 기대할 것 |
|---|---|---|---|
| 1 | 왼 엉덩이앞뒤 | 왼 허벅지를 **앞으로** 든다 | 숫자가 **커짐**(+) · 끝 +117 |
| 2 | 오른 엉덩이앞뒤 | 오른 허벅지를 **앞으로** 든다 | 숫자가 **작아짐**(−) · 끝 −117 |
| 3 | 왼 엉덩이좌우 | 왼 다리를 **바깥(왼쪽)으로** 벌린다 | 숫자가 **작아짐**(−) · 끝 −82 |
| 4 | 오른 엉덩이좌우 | 오른 다리를 **바깥(오른쪽)으로** 벌린다 | 숫자가 **커짐**(+) · 끝 +82 |
| 5 | 왼 엉덩이회전 | 왼 발끝을 **바깥(왼쪽)으로** 돌린다 | 숫자가 **작아짐**(−) · 끝 ±42 |
| 6 | 오른 엉덩이회전 | 오른 발끝을 **바깥(오른쪽)으로** 돌린다 | 숫자가 **커짐**(+) · 끝 ±42 |
| 7 | 왼 무릎 | 왼 무릎을 **굽힌다** (종아리 뒤로) | 숫자가 **작아짐**(−) · 끝 −117 |
| 8 | 오른 무릎 | 오른 무릎을 **굽힌다** | 숫자가 **커짐**(+) · 끝 +117 |
| 9~12 | 발목 크랭크 네 개 | **발판을 발끝 내려가게(숙임+)** 기울인다 | 왼: A− B+ / 오른: A+ B− |
| | | **발판을 안쪽으로(기울임)** 기울인다 | 왼: A− B− / 오른: A+ B+ |

3·4·5·6 번의 "바깥" 방향은 §1 에서 **좌우가 안 뒤집혀 있다**는 것을 확인하는
자리입니다 — 두 다리를 대칭으로 벌렸는데 숫자가 같은 방향이면 정상입니다.

## §5 결과를 어디에 적나

세 가지가 나옵니다.

1. **방향이 반대인 관절** → `joint_map_huphy.json` 의 그 줄 `sign` 을 −1 로.
2. **영점이 어긋난 관절** → 곧게 편 자세에서 읽힌 값을 `offset_rad` 로
   (또는 HUPHY 쪽 보정 파일 `calibration/*_leg_v1.0.json` 에).
3. 전부 맞으면 `side_mapping_verified` 를 `true` 로.

측정하는 동안 텔레메트리를 그대로 파일에 받아 둡니다(관절을 움직인 시각과 값이
남아야 나중에 따질 수 있습니다). 끝나면 이 문서에 표로 채우고,
`docs/128_huphy_change_ledger.md` 에 HUPHY 쪽 변경이 있으면 적습니다.
