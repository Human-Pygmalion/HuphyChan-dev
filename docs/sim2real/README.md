## 1. 10-13 실기 시험 — 무엇을 어떻게 돌렸나

`huphy-run --robot --policy stand --ankle-space ab --gain-scale A B --drain-ms D --hz H --log` 로 7 번 돌렸다.
- 게인 배율: 0.05/0.3, 0.05/0.5, 0.05/1.0, 0.1 전체, 0.05 전체. 앞은 발목을 뺀 관절, 뒤는 발목이다.
- 모든 실행에서 발은 바닥에 닿아 있었다. 크레인으로 받친 채 시작해 천천히 내렸다.
- 게인은 MIT 명령 12 비트로 버려진다 (Kp 0~5000, Kd 0~100). 배율 0.05 에서 발목 Kp 는 0 으로 전송됐다.
- `--hz 100` 은 실제 송신이 78 Hz 라 정책이 약 39 Hz 로 돌았다. `--hz 50` 은 20.0 ms 로 지켜졌다.
- 정책이 보는 관절각은 직전 주기에 받은 값이다. 한 주기 늦다.
- 응답 대기 2 ms 면 늦은 응답이 30 %, 4 ms 면 0.7~8.5 %. 유실은 1.4~3.1 % 였다 (한 실행 9.1 %).
- 안전 가드 (한계 −3°, 주기당 ±50°) 가 목표의 3~10 % 를 잘랐다.

근거: [`2026-10-13_huphy_archivedlogs_conditions.md`](2026-10-13_huphy_archivedlogs_conditions.md). 재현 도구: `tools/sim2real/huphy_log_conditions.py`.

## 2. IMU 부호 문제 (해결됨)

**무엇이었나.** EBIMU 는 각속도·가속도를 센서 도면 축 (x 앞, y 왼쪽, z 위) 으로 보낸다. 쿼터니언만은 항공기 관례 축 (x 앞, y 오른쪽, z 아래) 기준이다. HUPHY 가 쿼터니언을 그대로 시뮬레이션 규약의 식 $g = R^\top(0,0,-1)$ 에 넣었다. 그 결과 **투영 중력의 x 성분만** 부호가 반대가 됐다. y·z 는 두 번 뒤집혀 원래대로 돌아왔다. 그래서 수평에서 z = −1 이고 좌우 기울기도 맞아, "중력 하방 정상" 확인으로는 드러나지 않았다.

**결과.** 몸이 앞으로 숙이면 자이로는 "숙는 중" 이라고 말하는데, 중력은 "뒤로 젖혀졌다" 고 말한다. 시뮬레이션에서 중력 x 만 뒤집으면 게인 1.0 에서도 2.2 초 안에 8 번 중 8 번 넘어졌다.

**증거.**
1. 실기 로그 6 개 모두에서 자이로와 중력 변화율이 x 축 거울상이다. HUPHY 자체 검사 함수 `tools/imu_viewer.py analyze()` 를 그대로 돌려도 6 개 모두 "자이로 (1, −1, −1)" 로 판정했다. 시간 지연 0 ms 에서 상관 −0.70~−0.94 다.
2. 시뮬레이션 (학습에 쓴 fork·학습 플래그·배포 체크포인트) 은 같은 검사에서 정상이다 (기울기 x +0.82~+0.88, y +0.96~+1.06).
3. 데이터시트 축 정의로 계산하면 무작위 자세 10,000 개에서 정확히 x 만 반대다 (오차 1e-15).
4. **HUPHY `bb558c6` (2026-10-15) 가 같은 결론으로 고쳤다**: `to_quaternion` 이 `(w, x, −y, −z)` 를 반환. 정지·15° 기울임에서 가속도계와 0.002 안에서 일치 (고치기 전 0.5 차이).

**정정 이력.**
- 처음 가설 "쿼터니언 순서 `(z, y, x, w)` 가 틀렸다" (docs/151) 는 틀렸다. 순서는 맞았고, 축 부호 변환이 빠진 것이었다.
- "순서를 바꿔 읽으면 우연히 상쇄" 라는 표현도 틀렸다. 순서 오독과 축 변환 누락은 수학적으로 같은 결과를 낸다.
- 쓸 수 있는 로그는 7 개가 아니라 6 개다 (`0051ob4ms` 는 89 줄).

근거: [`2026-10-13_sim2real_gap_analysis.md`](2026-10-13_sim2real_gap_analysis.md) §4 (§4-1e 에 적대적 검토·블라인드 감사). 설명 페이지 [`2026-10-13_imu_frames.html`](2026-10-13_imu_frames.html) (3D, 브라우저로 열기). 영상 `docs/video/2026-10-14_sim_imu_tilt_xyz.mp4` (실시간). 기준표 `data/2026-10-14_sim_imu_tilt_table.csv`. 도구: `tools/sim2real/huphy_imu_frame_check.py`, `ebimu_frame_model.py`, `sim_imu_convention.py`, `sim_imu_tilt_table.py`, `render_imu_tilt_video.py`.

## 3. 게인 배율 — 학습 범위

시뮬레이션에서 게인 배율만 바꿔 서기를 시켰다 (게인 양자화·실기 타이밍 포함, 조건마다 8 번, 20 초).

| 게인 배율 | 바닥에서 | 크레인으로 받치고 1 → 0 으로 내림 |
|---|---|---|
| 1.0 | 8/8 섬 | 8/8 섬 |
| 0.8 | 8/8 섬 | — |
| 0.7 | 7/8 섬 | 8/8 섬 |
| 0.5 | 0/8 (2.7 초) | — |
| 0.05~0.1 | 0/8 (0.5~0.7 초) | 0/8 (7~9 초). 실기와 같은 크기의 흔들림 (행동 p99 5~6.5 대 실기 6~8) |

정책은 학습 게인에서 목표각과 현재각의 차이로 토크를 만든다 (서 있을 때 발목 크랭크 행동 ±1.8 ≈ 26°). 게인이 낮으면 관절이 목표를 못 따라가고, 직전 행동이 입력으로 되먹임돼 행동이 계속 커진다. **배율을 0.05 부터 올리며 보는 방식으로는 이 정책을 평가할 수 없다.**

근거: gap 분석 §2·§3. 도구: `tools/sim2real/real_condition_sim.py`, `gain_scale_sweep.py`, `huphy_obs_attribution.py`.

## 5. 밀기 회복 (10-15 질문 "게인 부족인가, 범위 밖인가")

서기 5 초 뒤 몸통 수평 속도에 한 번 0.1~0.7 m/s 를 더하고 6 초 관찰했다. 4 방향, 조건마다 3 번이다. 학습 때 밀기는 최대 0.7 m/s 였다.

| 게인 | 타이밍 | 넘어짐 /60 | 밀기 뒤 무릎 표준편차 |
|---|---|---|---|
| 1.0 | 이상적·실기 | 0 · 0 | 0.4° |
| 0.8 | 이상적·실기 | 0 · 0 | 0.6° · 0.9° |
| 0.6 | 이상적 | 0 | **10.9°** (서지만 밀면 크게 흔들림) |
| 0.6 | 실기 | 50 (35 번은 밀기 전에 넘어짐) | 17.4° |

**판단 (잠정).** "서기는 되고 조금 밀면 발산" 은 시뮬레이션에서 게인 약 0.6~0.7 의 모습이다. 게인이 학습보다 약하면 정책이 범위 밖으로 밀려난다. 즉 "게인 부족" 과 "범위 밖" 은 따로가 아니다. 배율 1.0 에서도 같다면 실기만의 차이를 봐야 한다 (실효 토크·마찰·백래시, 남은 IMU 치우침, 발목 링크).

근거: [`2026-10-15_push_divergence_check.md`](2026-10-15_push_divergence_check.md). 도구: `tools/sim2real/push_recovery_sim.py`. 결과 `data/2026-10-15_push_recovery_v11a.json`.
