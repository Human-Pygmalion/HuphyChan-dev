# Handoff — 실기 명령 지연·IMU 실측을 DR 에 반영 (2026-10-14)

## 배경 (3줄)
- 서기 정책 `rough_box_main_v11a` (checkpoint 11999) 를 실물 HUPHY 로봇에 배포했다가 서지 못하고 다리가 흔들렸다 (2026-10-13).
- 원인 분석은 끝났다. 주원인은 ① 실기 IMU 의 중력 x 부호 오류 (HUPHY 쪽, 개발자 확인 중) ② 학습 범위 밖의 낮은 게인 배율.
- 통신·타이밍 차이 (관절 관측 한 주기 지연, 응답 유실, 명령 지연) 는 시뮬레이션에서 단독으로는 무해했다. 이번 일은 이것들과 IMU 치우침을 **여유 확보용 DR** 로 학습에 넣는 것이다.

## 먼저 읽을 것 (이것 하나면 됨)
**`docs/sim2real/2026-10-14_dr_reference_latency_imu.md`**
- §0 표: 측정값 → mjlab 설정 항목 → 권장 범위.
- §3: 넣는 순서.
- 더 깊은 근거가 필요할 때만 그 문서 §4 의 경로를 따라간다.

## 할 일
1. #1 관절 관측 지연 (actor `motor_pos_history` 의 `delay_*_lag` 0~1) 과 #2 명령 지연 (액추에이터 `delay_*_lag` 0~1 물리 스텝) 을 넣는다. 기존 설정 항목이라 코드 변경이 필요 없다. 지금 학습 설정과 **단일 변인 A/B** 로 비교한다.
2. #3 응답 유실 (관절별 0~5 % 직전 값 유지) 은 새 관찰 손상 함수로 만든다.
3. #5 IMU 부착각 (`mjlab.envs.mdp.dr.site_quat` 를 `robot/imu_in_base` 에, 롤·피치 ±5°) 은 **개발자의 IMU 부호·부착 확인 결과를 받은 뒤** 범위를 확정한다.

## 하지 말 것
- **중력 x 부호 반전을 DR 로 넣지 말 것.** 실기 쪽 고정 오류라 고칠 대상이다.
- HUPHY 저장소 (biped 브랜치) 코드나 robot config 를 건드리지 말 것.
- 게인 배율을 낮추는 DR 로 저게인 실기 시험을 맞추려 하지 말 것. 실기 쪽에서 배율 ≥ 0.8 로 시작하는 것이 권고다.
