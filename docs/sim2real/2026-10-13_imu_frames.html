1. 약속: 축과 회전 방향

몸통 좌표계 B 는 x 앞, y 왼쪽, z 위입니다. 회전은 엄지를 축의 + 방향에 두고 나머지 손가락이 감기는 쪽이 + 입니다. 시뮬레이션의 IMU 는 base_link 에 회전 없이 붙어 있어 센서 좌표계가 곧 B 입니다.

+y 축 회전 = 앞으로 숙임

숙이는 동안 자이로 y +, 숙인 뒤 중력 x +.

+x 축 회전 = 오른쪽으로 기울임

기우는 동안 자이로 x +, 기운 뒤 중력 y −.

+z 축 회전 = 왼쪽으로 돎

중력은 바뀌지 않음. 도는 동안 자이로 z +.

2. EBIMU 안의 두 좌표계 (데이터시트)

같은 센서가 두 좌표계로 값을 냅니다. 둘 다 오른손 법칙이고, E 는 S 를 x 축으로 180° 돌린 것입니다.

5. 정책이 실제로 겪은 것

  1. 로봇이 앞으로 숙음 → 자이로는 "앞으로 숙는 중" (y +, 맞음), 중력은 "뒤로 젖혀져 있음" (x −, 틀림). 학습 때 본 적 없는 서로 모순된 조합입니다.
  2. 정책이 중력을 믿고 몸을 앞으로 보내려 하면 실제 숙임이 커집니다. 시뮬레이션에서 중력 x 만 뒤집으면 게인 1.0 에서도 2.2 초 안에 8/8 이 넘어졌습니다.
  3. 실기 로그 시작값: 정책이 받은 중력 x = +0.06~+0.12 ("앞으로 3.5~7° 숙임"). 부호를 바로잡으면 실제로는 뒤로 3.5~7° 젖혀진 상태였습니다.
  4. HUPHY 자체 검사 함수(tools/imu_viewer.py 의 analyze)를 실기 로그 6 개에 그대로 돌리면 6 개 모두 "자이로 y, z 가 중력과 반대" 로 판정합니다. 자이로 y·z 반대와 중력 x 반대는 같은 현상을 두 가지로 적은 것입니다.
