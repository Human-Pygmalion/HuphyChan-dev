## 1. 명령·관측 타이밍 (실기 한 주기)

```
ControlLoop.step (주기 = 1/--hz, 늦으면 따라잡지 않음)
 1. 관절 상태 = 직전 주기 collect() 가 받아 둔 값        ← #1 관절 관측 한 주기 지연
 2. IMU read() = 정책 호출 시점의 최신 패킷              ← #7 0~10 ms
 3. 정책 → 목표각 → 가드 → MIT 명령 (kp·kd 12 비트)
 4. send(): 두 다리 명령 송신                             ← #2 모터 도달 약 1~1.5 ms
 5. collect(): 응답을 drain_ms 까지 기다림. 못 받은 관절은 직전 상태 유지   ← #3
 6. 남은 시간 잠
```

### mjlab 에서 넣는 법

- **#1 관절 관측 지연.** 학습 설정 (`reference/rough_main/env.yaml` 의 `observations.actor.motor_pos_history`) 에 `delay_min_lag`, `delay_max_lag` 가 이미 있고 0 이다. 처리 순서가 "계산 → 잡음 → 지연 → 이력" 이라, 지연 1 을 주면 이력 두 프레임 `q(t-1), q(t)` 가 모두 한 칸씩 밀린다. 이것이 실기와 정확히 같은 모양이다 (실기 `q_prev` 는 직전 정책 호출 때의 `q`). 단위는 정책 주기 (20 ms). 관련 항목: `delay_per_env`, `delay_hold_prob`, `delay_update_period`.
- **#2 명령 지연.** 액추에이터 설정 (env.yaml `scene.entities.robot.articulation.actuators[*]`) 의 `delay_min_lag` / `delay_max_lag`. 단위는 물리 스텝 (`timestep 0.005`, `decimation 4`). 정의는 `mujoco-sim/mjlab/src/mjlab/actuator/actuator.py:67-85`.
- **#3 유실.** mjlab 에는 "확률적으로 직전 값 유지" 관찰 손상이 없다. 새로 쓸 경우 관절별 베르누이 마스크로 직전 관측을 유지한다. 시뮬레이션 재현 구현 예: `tools/sim2real/real_condition_sim.py` 의 `loss` (정책 바깥에서 관찰을 덮어씀).
- **#5 IMU 부착각.** `mjlab.envs.mdp.dr.site_quat` (`envs/mdp/dr/site.py:52`, RPY 섭동 합성) 를 reset 이벤트로 `robot/imu_in_base` 에 건다. 자이로 (`imu_ang_vel`) 와 위쪽 벡터 (`imu_upvector`) 가 같은 위치에 있어 둘이 함께 돌아가므로 일관성이 유지된다. 액터의 중력은 `projected_gravity_from_sensor` 라 이 회전을 반영한다. critic 의 `projected_gravity` (몸통 기준) 는 반영하지 않으므로 그대로 두면 critic 은 참값을 본다.

## 2. IMU 실측

| 항목 | 값 | 출처 |
|---|---|---|
| 출력 | 100.0 Hz, 쿼터니언·각속도·가속도 | docs/151 §1 |
| 자이로 정지 평균 (치우침) | x 0.110, y 0.151, z 0.416 °/s = 최대 **0.0073 rad/s** | docs/151 §1 (20 초, 2,000 표본) |
| 자이로 정지 표준편차 | 0.177 / 0.079 / 0.027 °/s = 최대 0.0031 rad/s | 〃 |
| 중력 성분 표준편차 (정지) | 0.0004~0.001 | docs/151 §2 |
| 자이로 양자화 | 0.01 °/s (1.75e-4 rad/s) | 실기 로그 최소 0 아닌 값 |
| 같은 값 반복 행 | 0.5~5.5 % (정지가 많은 실행 18 %) | 실기 로그 |
| 시작 시 중력 x (정책이 받은 값) | +0.06~+0.12. 부호를 바로잡으면 −0.06~−0.12 = 뒤로 3.5~7° | gap 분석 §1, §2 |

**부호 문제 (DR 대상 아님).** EBIMU 자세 좌표계는 자이로·가속도 좌표계를 x 축으로 180° 돌린 것이다 (데이터시트: Y·Z 반대, 자세 쪽 몸체 위 = −Z). HUPHY `gravity_from_quat` 이 변환 없이 $R^\top(0,0,-1)$ 을 써서, 정책 입력 중력 x 가 시뮬레이션과 반대가 된다. 적대적 검토와 블라인드 감사가 모두 "실기 입력의 중력·자이로가 x 축 거울상, 시뮬레이션은 정상" 을 확인했다. 센서 부착 방향은 미검증이고, 개발자의 실물 확인을 기다린다 ([gap 분석 §4-1e](2026-10-13_sim2real_gap_analysis.md) 의 판별표). **이 반전을 DR 로 학습시키면 정책이 앞뒤 기울기를 구분하지 못하게 되므로 넣지 않는다.**

**부착 위치.** HUPHY `config/robot_v1.0.yaml` 에 IMU `mount: right_leg` 로 적혀 있다. 데이터 (관절 속도와의 상관이 약하고 한쪽에 쏠리지 않음) 는 골반 부착을 시사하나 실물 확인이 필요하다. 다리에 붙어 있다면 #5 대신 위치 자체를 시뮬레이션과 맞춰야 한다.

## 3. 넣을 때 순서 (권장)

1. ★ 부호가 실기에서 고쳐졌는지와 부착 방향 확인 결과를 먼저 받는다 (§2). 그 전의 #5 범위는 잠정이다.
2. #1 (관절 관측 지연 0~1) + #2 (명령 지연 0~1 물리 스텝) 는 기존 설정 항목이라 코드 변경 없이 넣을 수 있다. 단일 변인 A/B 로 시작한다.
3. #3 (유실 유지) 은 새 관찰 손상 함수가 필요하다.
4. #5 (IMU 부착각) 는 수정 후 수평 정지에서 다시 잰 치우침으로 범위를 정한다.
5. #4 는 DR 이 아니라 실기 실행 옵션 (`--hz 50`) 으로 맞춘다.

시뮬레이션에서는 #1·#2·#3·#4 를 넣지 않은 지금 정책도 게인 1.0 에서 서 있었다 ([gap 분석 §3 표 1](2026-10-13_sim2real_gap_analysis.md)). 따라서 이들은 "실패 원인 제거" 가 아니라 "여유 확보" 용이다. 실기 실패의 주원인은 부호 오류와 낮은 게인 배율이었다.
