# 108. 학습 재개 전 품질감사와 실행 로드맵 (2026-09-01)

> 현재 점수: **80/100**. 연구·시각화·자동복구 장치는 강하지만, “시작 전 계약검사”와
> “완료까지 끊기지 않는 운영”이 약했다. 아래 5개 게이트를 채우면 같은 실패를 크게 줄일 수 있다.

## ELI5 요약

지금까지는 자동차를 잘 만들었지만 출발 전에 연료·브레이크·목적지를 한 번에 확인하는
체크리스트가 없었다. 그래서 달리다가 멈추고, 계기판 숫자의 뜻을 다시 확인하고, 같은 길을
재주행한 적이 있었다. 이제는 짧은 시동 시험을 통과한 차만 장거리 주행에 보낸다.

## 가장 큰 병목

가장 큰 병목은 GPU가 아니다. GPU는 16 GB 중 약 15.7 GB가 비어 있다. 실제 병목은
**실행 계약이 코드로 완결되지 않은 것**이다. 기존 정책에서 임시 고정했던 상체 관절을
열 준비를 했지만 보상 표·모터 정격·초기자세·
감시·측정 토글이 한 덩어리로 검증되지 않았다. 이 상태에서는 GPU를 오래 돌려도 결과를 버릴 수 있다.

### 최적해

본학습 전에 자동 preflight와 300~800 iteration 스모크를 통과시킨다. preflight는 GPU·RAM·disk,
단일 trainer, action/observation 차원, 모든 관절의 reward/rating 매칭, 정확한 환경변수 manifest,
watchdog/review cadence를 검사한다. 본학습은 1,000 iteration 또는 60분마다 자동 판정한다.

### 차선책

코드 변경을 최소화하려면 8,192 environments로 800 iteration만 먼저 돌려 영상·상체 사용률·NaN·
tracking을 확인한 뒤 16,384로 재시작한다. 안전하지만 예행 정책을 버리므로 시간이 더 든다.

## 대화 품질 감사

주 세션의 사람 요청 307개를 휴리스틱으로 분류하면 재확인·검증 요청 84개, 직접 오류 정정 34개,
기록·보고 요구 80개였다. 정확한 감정 점수가 아니라 반복 패턴을 찾기 위한 집계다.

반복 원인은 네 가지였다.

1. 계획이나 대기에서 턴이 끝나 다음 큐가 실행되지 않았다.
2. 데이터 열의 뜻·기준점·샘플링 주파수를 확인하기 전에 수치를 해석했다.
3. 학습·측정·렌더가 겹쳐 24 GB RAM에서 swap/`kswapd0` 병목을 만들었다.
4. 현재 파일·CAD·모델을 읽기 전에 이름이나 형상을 기억으로 추정했다.

앞으로 답변은 `결론 → 숫자 → 근거 파일 → 다음 자동 행동 → 중단 조건` 순서로 쓴다.
“진행 중”이라고 말할 때는 반드시 살아 있는 PID/산출물 시각/다음 판정 시각을 함께 적는다.

## 실행 순서와 기대효과

| 순서 | 조치 | 기대효과 |
|---:|---|---|
| 1 | 상체 reward/rating/초기자세 배선 수정 | 무효 학습 방지 — 효과 최대 |
| 2 | CPU 계약검사 + GPU 스모크 | 차원·NaN·OOM·토글 오류 조기 발견 |
| 3 | 16,384-env 본학습, 단일 heavy job | GPU 활용 극대화, RAM swap 방지 |
| 4 | 1,000 iter/60분 게이트 + watchdog | 중단·폭주·기록누락 방지 |
| 5 | 동일 프로토콜 v2s1-v2u1 A/B | 자유 상체의 실제 효과 분리 |
| 6 | 효과가 있으면 3 seeds | 우연을 결론으로 채택하는 오류 방지 |

## 80점에서 부족했던 20점

- 6점: reward schema가 새 DOF를 완전히 덮는지 자동검사 없음.
- 5점: RAM·disk·GPU를 함께 보는 시작 전 자원 게이트 없음.
- 4점: 단일 seed 결과를 설계 결론으로 확장할 위험.
- 3점: “진행 중” 문서와 실제 프로세스의 불일치.
- 2점: ELI5 문서와 상세 재현 manifest의 역할 분리가 약함.

## 본학습의 중단 조건

- swap 사용 증가, available RAM 6 GB 미만, GPU OOM, NaN 1건.
- 상체 관절 RMS가 사실상 0이거나 지속적으로 ROM 90% 이상 포화.
- 낙상률 0.5% 초과, command tracking이 같은 iteration의 v2s1보다 20% 이상 열세.
- watchdog/review 문서가 60분 이상 뒤처짐.

## 비교 때 반드시 고정할 변수

seed, 로봇 질량·관성, 발목 AB 모드, motor measurement와 T-N 제한, 초기 무릎 자세,
팔 기준 각도, command curriculum, P1 종료규칙, P2 DR window, entropy schedule, reward weight,
action scale, solver/contact 설정, num_envs, 측정 command grid·15초 dwell·200 Hz sampling.
