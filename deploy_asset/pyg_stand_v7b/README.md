# Pygmalion 서기 정책 v7b — 배포 꾸러미 (2026-09-21)

두 발 로봇 Pygmalion(다리만, 12 관절)이 **가만히 서 있게** 하는 강화학습 정책입니다.
이 폴더 하나로 실물에서 돌릴 수 있습니다. 시뮬레이터(MuJoCo, mjlab)는 **필요 없습니다.**

```bash
pip install numpy onnxruntime        # 이게 전부입니다
python3 policy_runner.py --contract deploy_contract.json --onnx policy.onnx --self-test
python3 example_loop.py              # 가짜 로봇으로 제어 고리 확인
```

## 0. 들어 있는 것

| 파일 | 무엇 |
|---|---|
| `policy.onnx` | **실제로 돌릴 신경망.** 관측 45 → 행동 12. 관측 정규화를 자기 안에 품고 있음 |
| `policy.pt` | 같은 정책의 PyTorch 저장본 (학습 재개·재수출용. 실물에서는 안 씀) |

| `motor_params.json` | 아래 §5 표의 원 수치 (학습 환경에서 직접 읽은 값) |
| `obs_adapter.py` | 센서값 → 관측 45 개 (numpy 만 씀) |
| `policy_runner.py` | 위를 묶은 `inference()`. **부르는 쪽은 이것만 쓰면 됩니다** |
| `example_loop.py` | 제어 고리 뼈대. 가짜 로봇이 들어 있어 실물 없이 돌아감 |

이 폴더에서는 같은 파일이 `policy.pt` 입니다 — 검증된 파일을 고치지 않으려고 그대로 뒀습니다.

## 1. 신경망과 제어 주기

| 항목 | 값 |
|---|---|
| 정책 신경망 | 다층 퍼셉트론 **45 → 512 → 256 → 128 → 12**, 활성함수 ELU |
| 출력의 뜻 | **관절 목표각** (토크 아님). 실제 토크는 모터 안의 위치 제어기가 만듭니다 |
| 제어 주기 | **50 Hz (20 ms)** — `deploy_contract.json` 의 `control_rate_hz` |
| 물리 적분 주기 (학습) | 5 ms, 제어 1 주기당 **4 번** (decimation 4) |
| 관측 정규화 | ONNX **안에 포함**. 날 것의 관측을 그대로 넣습니다 |

> **왜 토크가 아니라 목표각인가?** 신경망이 토크를 직접 내면 초당 50 번으로는 너무
> 느립니다. 모터는 그보다 훨씬 빠르게(수 kHz) 자기 안에서 돌고 있으므로, 신경망은
> "어디로 가라" 만 정하고 나머지를 모터에게 맡기는 편이 안정적입니다. 사족·이족보행
> 강화학습에서 사실상 표준입니다.

## 3. 관측 45 차원 — 칸마다 무엇인가

| 칸 | 이름 | 무엇 | 단위 | 학습 시 센서 잡음 (균등분포) |
|---|---|---|---|---|
| 0–2 | `base_ang_vel` | 몸통 각속도 (자이로 그대로) | rad/s | ±0.2 |
| 3–5 | `projected_gravity` | **몸통에서 본 중력 방향** 단위벡터 | — | ±0.05 |
| 6–29 | `motor_pos_history` | 관절 12 개 × **프레임 2 개** (상대각) | rad | ±0.01 |
| 30–41 | `last_action` | **정책이 직전에 낸 날 것의 값** | — | 없음 |
| 42–44 | `command` | 가고 싶은 속도 (앞뒤, 좌우, 돌기) | m/s, m/s, rad/s | 없음 |

잡음 칸은 **학습 때 일부러 넣은 값**입니다. 실물 센서가 이 정도 안에 있으면 정책이
본 적 있는 세상입니다. 넣지 말라는 뜻이 아니라, 실물 잡음이 이보다 크면 정책이
낯설어한다는 뜻입니다.

### 6–29 칸의 배치 (★ 틀리기 쉬움)

`[오래된 프레임의 관절 12 개][최신 프레임의 관절 12 개]` 순서입니다.
관절별로 묶이지 **않습니다**. 값은 관절각이 아니라 **기준자세각을 뺀 상대각**입니다.
이력이 모자라면(시작 직후) 가장 오래된 프레임으로 앞을 메웁니다.

### 관절 순서 (12 개, 이 순서가 전부에 공통)

```
0 R_hip_pitch   1 R_hip_roll   2 R_hip_yaw   3 R_knee   4 R_crank_A   5 R_crank_B
6 L_hip_pitch   7 L_hip_roll   8 L_hip_yaw   9 L_knee  10 L_crank_A  11 L_crank_B
```

발목은 **직접 구동하지 않습니다.** 크랭크 두 개(A·B)가 2-RSU 링키지로 발목
피치·롤을 함께 만듭니다(`PYG_ANKLE_MODE=AB`). 그래서 행동이 12 개입니다.

`obs_adapter` 는 관절값을 **목록이 아니라 이름을 키로 하는 사전**으로 받습니다 —
목록이면 부르는 쪽이 순서를 틀려도 아무도 모르기 때문입니다.
쓸 이름은 `pol.joint_names` 가 알려 줍니다.

## 4. 행동 12 차원 — 각도로 바꾸는 법

```
목표각[rad] = 오프셋 + 0.25 × 행동값        그 뒤 관절마다 clip
```

배율은 12 관절 **전부 0.25** 입니다. 즉 행동 ±1 이 기준자세에서 ±0.25 rad(±14.3°).
오프셋은 곧 **기준자세각**입니다.

| # | 관절 | 오프셋 = 기준자세 [rad] | [deg] | clip [rad] |
|---|---|---|---|---|
| 0 | `R_hip_pitch_joint` | −0.17500 | −10.03 | [−1.9679, +0.3098] |
| 1 | `R_hip_roll_joint` | +0.00000 | 0.00 | [−0.3403, +1.3875] |
| 2 | `R_hip_yaw_joint` | +0.00000 | 0.00 | [−0.7069, +0.7069] |
| 3 | `R_knee_joint` | +0.35000 | +20.05 | [+0.1047, +1.9897] |
| 4 | `R_crank_A_joint` | +0.14395 | +8.25 | [−1.0800, +1.0800] |
| 5 | `R_crank_B_joint` | −0.14706 | −8.43 | [−1.0800, +1.0800] |
| 6 | `L_hip_pitch_joint` | +0.17500 | +10.03 | [−0.3098, +1.9679] |
| 7 | `L_hip_roll_joint` | +0.00000 | 0.00 | [−1.3875, +0.3403] |
| 8 | `L_hip_yaw_joint` | +0.00000 | 0.00 | [−0.7069, +0.7069] |
| 9 | `L_knee_joint` | −0.35000 | −20.05 | [−1.9897, −0.1047] |
| 10 | `L_crank_A_joint` | −0.14389 | −8.24 | [−1.0800, +1.0800] |
| 11 | `L_crank_B_joint` | +0.14687 | +8.42 | [−1.0800, +1.0800] |

**왼쪽과 오른쪽의 부호가 반대**입니다(엉덩이 피치 −10.03° 대 +10.03°). 미러 규약이고,
바꾸면 로봇이 뒤로 걷습니다. `pol.default_pose` 로 그대로 읽으십시오.

기준자세는 **살짝 웅크린 자세**입니다 — 엉덩이 10°, 무릎 20°, 크랭크 ±8.3°
(`PYG_INIT_BENT=1`). 곧게 선 자세가 아닙니다. 정책을 켜기 전에 로봇을 여기로
보내 두십시오.

## 5. 모터 파라미터 — 학습이 가정한 값

정책은 **이 이득으로 돌아가는 모터**를 전제로 학습했습니다. 실물 이득이 많이 다르면
같은 목표각이 다른 움직임을 냅니다.

| 관절 묶음 | 모터 | **Kp** (강성) | **Kd** (감쇠) | 토크 한계 | 속도 한계 | 회전자 관성 | 정지마찰 |
|---|---|---|---|---|---|---|---|
| `*_hip_pitch`, `*_hip_roll` | RobStride **RS04** | **150.0** | **6.0** | 120 N·m | 15 rad/s | 0.0773 | 0.519 |
| `*_knee` | RobStride **RS04** | **220.0** | **6.0** | 120 N·m | 15 rad/s | 0.0773 | 0.519 |
| `*_hip_yaw` | RobStride **RS03** | **150.0** | **6.0** | 60 N·m | 20 rad/s | 0.0638 | 0.251 |
| `*_crank_A`, `*_crank_B` (발목) | RobStride **RS03** | **22.266** | **1.414** | 60 N·m | 20 rad/s | 0.0638 | 0.251 |

단위: Kp 는 N·m/rad, Kd 는 N·m·s/rad, 회전자 관성은 kg·m²(반사 관성), 정지마찰은 N·m.

**발목 크랭크의 이득이 유독 낮습니다**(22.3 / 1.41). 링키지를 거쳐 발목에 도달하므로
크랭크 축에서 본 값이 작습니다. 실수로 다른 관절과 같은 값을 넣으면 발이 덜덜거립니다.

> **주의 — `damping` 이라는 이름이 두 군데 있습니다.** 위 표의 Kd 는 **제어 이득**입니다.
> 모형 파일에는 관절의 **점성 마찰**도 `damping` 이라는 이름으로 따로 있습니다.
> 자리를 바꾸면 안 됩니다.

### 관절 가동범위 (학습 모형 기준)

| 관절 | 범위 [deg] | | 관절 | 범위 [deg] |
|---|---|---|---|---|
| `R_hip_pitch` | −120.00 ~ +25.00 | | `L_hip_pitch` | −25.00 ~ +120.00 |
| `R_hip_roll` | −25.00 ~ +85.00 | | `L_hip_roll` | −85.00 ~ +25.00 |
| `R_hip_yaw` | −45.00 ~ +45.00 | | `L_hip_yaw` | −45.00 ~ +45.00 |
| `R_knee` | 0.00 ~ +120.00 | | `L_knee` | −120.00 ~ 0.00 |
| `R_crank_A/B` | −68.75 ~ +68.75 | | `L_crank_A/B` | −68.75 ~ +68.75 |

**크랭크 ±68.75° 는 아직 실물로 확인되지 않았습니다.** 손으로 돌려 본 범위는 ±46°
였습니다(원 저장소 할 일 #4). 실물에서 크랭크를 크게 움직이기 전에 하드스톱을
직접 확인하십시오.

## 7. 돌리는 코드 (이게 전부입니다)

```python
from policy_runner import StandingPolicy

pol = StandingPolicy.from_files("deploy_contract.json", "policy.onnx")
pol.self_test()          # ★ 참조 입출력 대조. 한 번은 반드시 (아래 §9)

# 정책을 켜기 전에 로봇을 기준자세로. 천천히 보내십시오.
for name, rad in pol.default_pose.items():
    motor[name].move_to(rad)

pol.reset()              # 관절 이력과 직전 행동을 비움. 세울 때마다

while True:              # 정확히 50 Hz — 20 ms 마다
    targets = pol.inference(
        gyro=imu.gyro_xyz,                    # rad/s, 몸통 기준
        projected_gravity=imu.gravity_xyz,    # 단위벡터, 서 있으면 (0, 0, −1)
        joint_pos={n: motor[n].position for n in pol.joint_names},  # rad, 이름 사전
        command=(0.0, 0.0, 0.0),              # 제자리 서기
    )
    for name, rad in targets.items():
        motor[name].set_position(rad)         # 관절 목표각 [rad]
```

### 제어 주기

정책은 **자기가 20 ms 마다 불린다고 가정하고** 학습했습니다. 30 ms 마다 부르면 정책이
보는 세상이 느려진 것과 같아서, 넘어지지는 않더라도 학습 때와 다르게 움직입니다.
`policy_runner` 는 최근 51 주기의 **중앙값**이 20 % 넘게 어긋날 때 한 번 알려 주고
계속 돕니다 — 한 번의 딸꾹질로는 말하지 않고, 달리는 로봇을 예외로 세우지도 않습니다.

## 8. 반드시 걸려 넘어지는 지점 네 개

### ★ 함정 1 — 중력 방향의 **부호**

`projected_gravity` 는 **중력이 가리키는 쪽**이라 서 있으면 `(0, 0, −1)` 입니다.
관성측정장치는 흔히 **위 방향** `(0, 0, +1)` 을 줍니다. **부호만 다르고 크기가 같아서**
길이 검사도 자릿수 검사도 전부 통과하고, 로봇은 거꾸로 매달린 줄 알고 움직입니다.

`obs_adapter` 가 **처음 다섯 주기 동안 직접 검사**해서 모터가 돌기 전에 멈춥니다.

### ★ 함정 2 — `last_action` 은 목표각이 아니다

관측 30–41 칸은 정책이 **직전에 낸 날 것의 값**입니다. 배율 0.25 와 오프셋을 입히기
**전** 숫자입니다. 관절 목표각을 대신 넣으면 크기가 12 로 같아서 아무 오류 없이
통과하고, 정책은 평생 본 적 없는 값을 받습니다.

**`StandingPolicy` 가 이 값을 안에 들고 다닙니다.** 부르는 쪽은 신경 쓰지 마십시오.

### ★ 함정 3 — 관절 이력의 배치

§3 참조. `[오래된 12][최신 12]`, 상대각.

### ★ 함정 4 — 관절 순서와 이름

§3 참조. 사전으로 주고받습니다.

## 9. 모터를 켜기 전에

### 9-1. 참조 입출력 대조

명세 안에 관측 16 개와 그 정답 행동 16 개가 들어 있습니다. 학습 기계에서 만든 정책이
로봇의 중앙처리장치와 ONNX 판에서도 같은 값을 내는지는 **돌려 봐야** 압니다.

```bash
python3 policy_runner.py --contract deploy_contract.json --onnx policy.onnx --self-test
```

이 꾸러미의 기준값: **최대 차이 2.437e-06** (허용치 1e-04). 여기서 어긋나면 명세와
정책의 짝이 틀렸거나 이 기계의 ONNX 판이 다른 것입니다. **모터를 켜지 마십시오.**

### 9-2. 빈 돌리기 — 로봇 없이 배선·단위·주기 확인

```bash
python3 policy_runner.py --contract deploy_contract.json --onnx policy.onnx --dry-run 20
python3 example_loop.py --seconds 30
```

`example_loop.py` 의 `FakeRobot` 을 여러분의 모터·관성측정장치로 바꾸면 그대로 실물
제어 고리가 됩니다.

## 10. 이 꾸러미가 **하지 않는** 것

의도적으로 비워 둔 자리입니다. 임의로 넣으면 진짜 필요할 때 왜 멈췄는지 모르게 됩니다.

* **안전 정지·타임아웃이 없습니다.** 필요하면 부르는 쪽에서 감싸십시오.
  (§6 의 "들어 올리면 휘두른다" 때문에, 테더 작업에는 바깥에서 모터를 끄는 수단을
  두시는 편이 좋습니다.)
* **PD 이득을 설정하지 않습니다.** §5 의 값은 *학습이 가정한 값* 이고, 실제로 모터에
  넣는 것은 로봇 쪽 설정입니다.
* **관측 정규화를 하지 않습니다.** ONNX 가 자기 안에 품고 있습니다. 명세의
  `obs_normalizer_mean/std` 는 진단용입니다.
* **공중에 들렸는지 판정하지 않습니다.** 이 정책에서는 토크로 가르는 것이
  **실측으로 불가 판정**이 났습니다 — 고정 문턱도, 모형 기반 예측도 땅과 공중의
  분포가 완전히 겹칩니다(원 저장소 `docs/148` §5).
