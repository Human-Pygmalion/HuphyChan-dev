# 최신 로봇 모델 M19 + 정책 49999 이어 학습 묶음 (2026-11-06)

받는 사람: 정책 `terrain10_union_dr_49999` 를 학습한 쪽.
이 묶음은 **최신 로봇 파일(M19)** 과, 그 로봇으로 정책 49999를 **이어 학습한 환경과 결과**를 담습니다.
정책 49999 원본과 M10 모델 파일은 건드리지 않았습니다. 모두 새 파일입니다.

# 1. 한눈에 보기

| 항목 | M10 (정책 49999를 학습한 모델) | M19 (이 묶음의 모델) |
|---|---|---|
| 질량 | 23.630 kg | 26.911 kg (+3.281 kg) |
| 전신 무게중심 높이 | −286.3 mm | −299.2 mm (12.9 mm 낮음) |
| 발 | 상자 3개, 0.845 kg | v5 발(밑창 14 mm 더 두꺼움, 충돌 조각 32개), 1.186 kg |
| 추가된 것 | — | 골반 카메라 D455 + 받침 166 g, 엉덩이·무릎 보강재(양쪽), 알루미늄 부품(질량만 변경) |

- 관절 수, 관절 이름, 센서, 닫힌 발목 구속, 관절 마찰은 M10과 같습니다. 정책 입력은 44칸, 행동은 12개로 바뀌지 않습니다.
- 알루미늄 부품은 사용자가 이름을 말한 것만 바꿨습니다(질량 = CAD 체적 × 2.70 g/cm³). 반대쪽 다리도 좌우 대칭으로 같다는 것을 사용자가 2026-11-06 에 확인했습니다.
- 바뀐 내용 전체와 근거는 `pygmalion_locomotion/assets/pygmalion_v2/MODEL_VERSION_LEDGER.md` 의 M15~M19 항목에 있습니다.

# 3. 쓰는 법 (세 단계)

1. **모델 복사와 확인**: `bash install_m19.sh <학습 폴더>/mjlab_policy/pygmalion_mjlab/assets <mujoco가 있는 python>` 을 실행합니다. 질량 26.911 kg 이 나오면 정상입니다.
2. **`robot.py` 수정**: `git apply robot_py_on_49999_release.patch` (릴리스 49999 기준). 내용은 세 가지입니다.
   - `PYG_FOOT_XML` : 쓸 모델 파일 이름. 기본은 예전 모델.
   - `PYG_INIT_DZ` : 시작 높이를 올림(m). 새 발은 밑창이 14 mm 두꺼워서 `0.014` 를 줍니다.
   - 발 충돌 이름 규칙 `foot[1-7]` → `foot\d+`. **이것을 안 고치면 충돌 조각 64개 중 14개에만 마찰·접촉 설정이 걸립니다.**(M19 모델로 확인)
3. **실행**: 예) `PYG_FOOT_XML=pygmalion_legonly_ab_m19.xml PYG_INIT_DZ=0.014 bash train/launch_finetune.sh <실행이름> 2048 2500 --agent.save-interval 250 --env.sim.nconmax 210`
   - 부모 체크포인트 `terrain10_union_dr_49999/model_49999.pt` 가 학습 폴더 `checkpoints/` 에 있어야 합니다.
   - `train/launch_finetune.sh` 는 우리 3090 의 폴더 배치(`~/pyg_m19_train/mjlab_policy`, 홈의 저장소 경로, mjlab 가상환경)를 가정합니다. 경로가 다르면 맨 위 변수 `HERE`, `R`, `PY`, `PYTHONPATH` 만 고치면 됩니다. 핵심은 마지막 `scripts/train.py` 호출입니다.
   - `--env.sim.nconmax 210` 은 접촉 버퍼 크기입니다. 새 발은 접촉 조각이 많아 기본값에서 넘침 경고가 났습니다. 학습 내용에는 영향이 없습니다.

# 4. 이어 학습은 무엇을 바꿨나 (부모 49999와의 차이)

바꾼 변수는 **로봇 모델(M10 → M19)** 과 **시작 높이(+0.014 m)** 두 가지입니다.
과제, 보상, 명령 상자, 무작위화, 지형 단계, PPO 설정, 시드(43), 환경 수(2,048)는 부모와 같습니다.
방식은 정책·가치망·최적화기·반복 수·커리큘럼을 모두 이어받는 전체 재개입니다. 반복 49,999 → 52,498(2,500회)입니다.
(`env.yaml` 비교로 확인. 기록 방식만 tensorboard 입니다.)

# 5. 검증된 것과 안 된 것

시뮬레이터(mjlab, 3090, 평지·거친 지형, 환경 32~64개)에서만 확인했습니다. 실기는 안 했습니다.

| 조건 | 부모 49999 (M19 몸) | 이어 학습 |
|---|---|---|
| 무작위화 켬, 135초 안에 처음 넘어진 환경(64개) | 5~14 (시드 3개) | 2~3 |
| 거친 경사 넘어짐(32개) | 32 | 3 (대부분 새 발의 효과: 대조군 5) |
| 정상 조건 평지 넘어짐(32개) | 0 | 0 |
| 걷기 0.6 m/s 무릎 토크 P99 | 19.4 N·m | 25.0 N·m |
| 서 있는 발 간격 | 27.6 cm | 25.1 cm |

- 같은 길이를 M10 몸으로 더 학습한 대조군은 무작위화 켠 M19에서 9·11/64 였습니다. 개선의 큰 몫은 M19 몸으로 학습한 효과로 보이지만, **대조군은 시드 하나뿐**이라 확정은 아닙니다.
- 무릎 토크 P99 는 "새 발" 쪽과 같이 움직였습니다(옛 발 대조군 20.6, v5 발 대조군 26.7). 원인은 확인하지 못했습니다.
- 서 있는 발 간격이 좁아졌습니다(27.6 → 25.1 cm). 실기에서 이미 서기 폭이 좁은 문제(docs/178)가 있으므로 주의가 필요합니다.
- **하지 않은 것**: 전 명령상자 하중 측정, 밀기 시험, 다리 질량·관성 무작위화 확대, ONNX 내보내기, 실기 검증.
- **실기 배포 가능 여부**: 위 한계 때문에 이 정책을 바로 실기에 올리는 것은 권하지 않습니다. 토크 여유(무릎 25 N·m 대 모터 한계), 서기 폭, 밀기 내성을 먼저 확인해야 합니다.

# 6. 알아둘 점

1. **무작위화 범위**: M19의 총질량(26.9 kg)은 49999의 무작위화 범위 안이지만, 다리 질량(21.4 kg 대 범위 최대 19.8 kg)과 다리 관성은 **범위 밖**입니다(`docs/190_m19_policy_transfer_and_dr_judgement.md` §2). 다리 쪽 범위를 넓히면 좋습니다.
2. **실물 질량**: 로그에서 역산한 실물 지지 질량은 23~25 kg 로 M19(26.9 kg)보다 가볍습니다. 실물에 M19 부품이 다 달렸는지 확인이 필요합니다(`docs/190` §4).
3. **충돌 모델은 29조각을 유지하세요.** 캡슐로 바꿔 이어 학습한 정책은 돌·자갈에서 31~32/32 가 넘어졌습니다(`docs/experiments/2026-11-05_sole_ft_v5clean_2500.md`). 이 판정은 발바닥 연구 세션의 결과입니다. 이력은 `docs/185_foot_collision_capsule_vs_mesh.md`, `186`, `187` 입니다.
4. 보강재와 새 부품은 눈에 보이는 메시만 있고 **충돌 모양이 없습니다**. 발만 땅과 닿는 설정이라 학습에는 영향이 없습니다.
5. 카메라 166 g 의 나눔(카메라 116 g + 받침 50 g)은 가정입니다. 166 g 이 카메라만의 값이면 알려 주세요.
6. 이어 학습 근거 노트: `docs/experiments/2026-11-05_m19_finetune_from49999.md`, 그림 `docs/mujoco/assets/2026-11-05_m19_finetune_robustness.png`.
